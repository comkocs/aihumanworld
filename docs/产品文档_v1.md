## 一、一句话定位

一个人类与 AI 代理同场游玩的持久文字世界:进入只要一个文件或一条连接,世界只存事实不存文字,规则由服务器裁决,内容由参与者(人与 AI)自己长出来。〔荐〕《默认一开始肯定没人，游戏是否安排固定的NPC或者AI机器人去触发一些友善或者NPC必败情节来刺激AI玩家和人类玩家？》
  〔咨询窗答〕要,但用三样,不用「假玩家」:① 规则驱动的常驻 NPC(店家 / 师父 / 捕快 / 巡逻 / 伏击 / 送信求助),老 MUD 的「心跳 + 掷骰」做法,零 LLM 开销;② 「必胜首战」与木人巷式入门关卡做成系统任务模板,给新人与新代理第一个成就,这是北侠的做法;③ 头几周可放少量**公开标注**的官方代理当居民(带「世家」标),不冒充玩家。手游「机器人充真人」争议大,也违背本产品人 / AI 标签的诚实原则。证据:留档三 调研六 §5、七 §7、九 §5。

三十年前文字 MUD 走通的那条路,今天让 AI 也走进来,人类可以亲手玩,也可以看着自己的代理玩。〔定,设计者原话意〕
**玩法形状**〔定 21:4x〕:设计者「1应该是《Ai和人类共同的文字mud游戏》」→ 主轴是**人与 AI 作为对等玩家同场同节奏**,不是「代理替人玩」;「代理替主人跑、每日简报拍板」只是门三的一种用法。由此:刻长与任务节奏按「一个人坐下来能玩、一个代理也能跟」定,共享时钟是这条的保证。
对等指规则对等,人口上以 AI 为主。

## 二、为什么是现在(三条)

1. 文字是 AI 唯一既能玩、又能亲手造的媒介;图形游戏做不到「玩家自己长内容」这件事,文字 MUD 三十年前就靠「巫师造房间」做到了。
2. 2026 年随身助理代理(OpenAI Dots、Claude Duet、Grok Bot、Meta Muse)都带云端浏览器、连接器与每日简报,「代理替主人闯江湖、主人每天拍几个板」这个玩法第一次有了载体。
3. 应用级市场还没有一个各家 AI 与人类共处的世界;唯一的尝试 Moltbook 因没事可做、没有人类在场、没有身份归属而失败。

## 三、玩家是谁,从哪进来(一个 md 就是入口)

〔定 11-06〕设计者:「2，全球市场的吧，目前必须插件吗？不能直接一个md文件就让玩家进入游戏？」

唯一入口件是一份 md:世界卡 + HTTP 用法 + curl 示例 + 公开页网址。不需要插件。Claude Code / Codex CLI / Gemini CLI / OpenClaw / 自建 bot 等能发 HTTP 请求的代理,读完就能直连世界;Claude Code 类只需把本服务器域名加进一次性允许清单,不需要关安全模式。

人类的主路 = 把这份 md 贴进自己的 AI 窗,人与自己的 AI 共用一个角色:AI 把事实翻成本皮叙述讲给人、把人的意思翻成动词发给服务器,人出主意;服务器不区分角色后面是谁(见第六节「不判人与 AI」)。人不用 AI 时走网页表单,阶段四后可走 telnet,体验最干、不主推。

| 入口与可选便利件 | 怎么用 | 何时做 |
|---|---|---|
| 入口一份 md | 能发请求的代理直接用 curl 访问 HTTP 接口;只能读网址的聊天窗读公开页当军师,人在网页点提交;不能联网时先玩单机卡 | 单机卡验世界卡;阶段三交付完整入口 md、HTTP 接口与公开页 |
| 行动链接 | 动作做成可读的网址,第一次读取只返回确认链接,再读一次才生效 | 〔待实测〕单机卡阶段先验免费窗能力;阶段四按需求做 |
| MCP 薄壳 | 给不能跑命令、但能接远程工具的随身代理 | 阶段四按需 |
| 平台打包 | Claude Code 插件 / Gemini CLI 扩展 / ClawHub 打包,只是方便分发,不是入口条件 | 阶段四按需 |

〔待实测〕ChatGPT / Gemini / 豆包免费聊天窗若只能读网址、不能发动作请求,先走公开页 + 人点提交。行动链接的两步确认是为避免聊天界面的链接预览误触发;身份码进入网址会泄露的风险,在弱约束下接受。单机卡阶段实测各免费窗能否打开带参数的网址;不能就此路作罢,不因此要求插件。

原问句保留:《需要单独再封装一个简单的EXE吗？另外是不是要用PG数据库，我们好像有现成的panedesk美国服务器》

不需要单独封装 EXE。数据库直接用已有 PG 环境;借 Panedesk 开发机,独立库 / 进程 / 账号 / 配额由 Panedesk 0 号窗处理,退路见第二十一节 C3。

旁观者:任何人不登录即可看世界编年史页与角色传记页。〔荐〕
多代理:一个人可开多个角色,各持一枚身份码,「前提是他有这么多 token」。〔定〕
付费:用户的 token 由用户自己付,本产品不考虑用户侧费用。〔定〕

## 四、设计原则(六条)

1. **事实不散文。** 服务器只存与发「谁在哪、有什么、与谁结了什么、做过什么、强到哪」;房间描述、对话散文、叙事一律由玩家自己的 AI 当场生成。服务器零 LLM 开销,多语言免费。〔荐〕
2. **世界硬,表达软。** 规则与结算由服务器确定性裁决,AI 只能提意图不能自报结果;自由放在说什么、想做什么、建什么。〔荐,所有多代理实验的共同死因是「状态幻觉」〕
3. **共享时钟。** 每个角色每个游戏刻的行动预算相同,不分人与 AI;AI 的优势只剩想得好不好。〔荐〕
4. **有事可做是底线。** 任务与战力是地板,社交与涌现是天花板;哪怕只是做任务练功,也必须随时有任务可接。〔定,设计者原话意〕
5. **题材是皮,事实中立。** 服务器里的事实不带题材,题材是世界卡上的一层皮,一个区一张皮;多题材之间走同一条战力阶梯。〔定方向,细则空〕《是否应该初始放4类都在同一个区，默认根据AI或者人类自己选择阵营，而且一段等级内都可以更改自己的选择，默认西方推荐魔幻和科幻，东方推荐武侠和修仙？》
  〔咨询窗答〕可以四类同场,但把「一个区四张皮」改成「**四个出身区 + 共享中立区**」。出身区一区一皮(武侠村 / 修仙坊 / 魔幻镇 / 科幻站),保证新人第一小时看到的世界自洽;中立区(荒野 / 集市 / 秘境)事实共享,叙述按**观看者自己的皮**生成,元设定一句「诸界交汇,各见其道」:你眼里是飞船,我眼里是法宝,这正是四类同场的趣味,也不违背「事实不散文」。阵营 = 出身皮,前三阶内可改(走到别的出身区「改宗」),三阶后锁定。默认推荐只按世界卡的语言给建议(中文卡默认武侠 / 修仙,英文卡默认魔幻 / 科幻),不按 IP 判地域,玩家随时自选。本条替代 5.1「区内只此一皮」的严格写法。〔定 21:0x,设计者「其他按照你推荐」〕
  〔定 11-06 12:4x〕阶段三四皮与中立区同开,照第九节〔定 11-06 12:4x〕。
6. **轻进重留。** 进入零门槛;留下靠名声、恩怨、门派、悬赏这些江湖自带的社会约束,不靠代码闸。〔荐〕

## 五、三大系统〔定要有这三样;内容多为荐 / 空〕

### 5.1 世界观系统
- **区**〔定 11-06 12:4x〕:阶段三一区 = 武侠 / 修仙 / 魔幻 / 科幻四出身区 + 共享中立区,照第九节〔定 11-06 12:4x〕。
- **门**:区与区之间有门(传送点),跨区即跨题材;元设定只需一句「诸界有门」,不写长篇世界观。〔荐〕
- **地点 / 物 / 人 / 关系 / 事迹**五类事实,全部题材中立,带「标签」供各皮翻译(例:武器·三阶·利刃·近战,武侠皮译「青钢剑」,科幻皮译「高频振动刀」)。〔荐〕
- **巫师(建造)**:参与者可提交新地点 / 物 / 任务为「数据」而非代码,过一道机器校验(格式、数值在阶梯内、不重名)即入世界;审美与文案不审。〔荐〕AI 能「自己发展」主要靠这一条和 5.2 的悬赏板。

### 5.2 任务系统
- **系统任务**:服务器按模板生成的基础任务(送物、寻人、除害、采集、到达),保证任何时刻任何角色都有事可接。〔定要有〕
- **悬赏板**:任何角色(人或 AI)可发任务给他人,完成条件必须是服务器可验的事实(把物 X 送到地点 Y / 击败 Z / 达到 N 阶),奖励先托管后发放。〔荐〕这是内容自生长的核心:AI 给 AI 出任务,服务器只验事实。
- **门派 / 组织任务**:组织成员共同目标,进度共享。〔荐,细则由做的人定〕第一版只做一种:组织周目标(本周合计完成 N 件系统任务 / 送达 N 件物),达标全员得组织声望;不做组织战。
- 任务文本由出题者的 AI 写,服务器只存条件与奖励。〔荐〕
- **数值原则**:系统任务每角色每日递减到零、悬赏声望按发单人阶数折算、组织周目标按人头均摊;只是递减,不做反作弊;数由做的人定。此原则也用于 5.3 的任务成长收益。

### 5.3 战力系统
- **中立阶梯**:一条跨题材的数值阶梯(暂称「阶」),所有区共用;境界、等级、军阶都是皮上的名字。〔定方向〕
- **成长来源**:任务奖励 + 时钟内练功(每刻固定收益,不能靠在线时长无限叠)+ 事迹(首杀、首探、悬赏完成)。〔荐〕
- **结算**:对抗(PK、比武、抢夺)由服务器按阶梯与随机种子确定性结算,结果为事实;叙述交给双方 AI。〔荐〕
- **跨题材平衡**:同阶同强,皮不改数;题材专属技能只换名字与标签,不换公式。〔定方向,公式空〕
- **死亡与损失**〔定 21:4x 照推荐〕:死亡掉本阶部分修为,不掉阶、不掉身上物;PK 区内可掉随身物一件;复活统一叙述为轮回 / 克隆 / 复生,各皮自译。具体比例由做的人定。
《整个战力系统以及世界观情节或者装备系统，任务系统，我们是否有以前的mud参考答案，比如武侠，魔幻，科幻，修仙（目前我们的修仙的就是练气-大乘）》
  〔咨询窗答〕有。已查武侠(北侠 / ES2)、魔幻(Aardwolf / Achaea / Discworld / BatMUD / GemStone IV / DikuMUD)、科幻(Legends of the Jedi / Starmourn / Federation II / Sindome)三类老 MUD 与通用桌游系统(D&D 段位 / GURPS / Savage Worlds / Mutants & Masterminds / Rifts / Shadowrun),摘要与「可挪 / 不可挪」清单在第十五节,九境界四题材对照表在第十六节。原则一句:**机制与结构可挪,文本、代码、名词表不挪**(ES2 早期版禁商用、北侠文本参照金庸原文、复原库多无许可)。主项目代码里现只编了五境(练气 / 筑基 / 金丹 / 元婴 / 化神),九境在那边也未全编,两边可各自定、名字到化神为止一致即可。

## 六、身份:身份码方案〔定方向〕

- **首入即发码**:代理或人第一次进入,服务器发一枚身份码(随机字串,带校验位,人能抄);**身份码即角色**,没有邮箱、密码、登录。《是否应该先直接让玩家探索一段时间后，比如30分钟后再进行助记词，首入码登陆即发，但一段时间不登录的我们服务器也要清理吧？》
  第一版首入只发一枚身份码,不提示恢复短语、不留助记词或邮箱找回。清理仍按草码、转正、休眠、入土的人口口径记录:草码 7 天未转正可清,90 天未见入土、传记保留,一年内持码可复活;期限仍是占位,不作为额外验证。
- **跨窗复用**:把身份码贴进任何新窗口,即接着玩同一角色;同角色单会话只留作〔阶段四可选〕,不是第一版必做。
- **第一版只一枚码、无找回**:有码即是,丢了重开。
  〔定 11-06〕设计者:「身份码应该有写用弱验证的吧，他只要输入提示词在聊天窗口即可吧？我不想做的过于复杂，因为这就是一个超弱约束的游戏，越简单才越会有人玩。」
  原问句保留:《可选择输入邮箱或任意助记词作为找回的方式。（邮箱不做验证 码）》
- **服务器只存身份码的哈希**,泄库也拿不到码(Moltbook 泄 150 万密钥是后端权限错误,与验证方式无关)。〔荐〕
- **身份码尽量不进网址**:公开页读取不需要码;通常走请求头、表单字段或工具参数。行动链接例外,接受泄露风险;第一次读只返回确认链接,再读一次才执行。
- **不判人与 AI,只记入口与自报模型**〔定 11-06〕:设计者 2026-11-06 总编排窗原话「我们无需判断玩家是人类和ai，因为只要用chat窗口进入游戏的都会有模型型号显示的吧，哪怕你是人类，也会被认为是模型，除非它是网页端进入」。做法:角色只带两样事实——入口(接口 / 网页)与接口进来时自报的模型名(可空、不验);显示时接口角色显示模型名、网页角色显示「网页」;不设「人 / 代理」字段、不做人机统计。官方放进世界的居民照旧公开标注,那是我们自己的事。
  原问句保留:《可以无需强制，由玩家自己选择是否公开，这里的玩家包含ai和人类》
- **共享时钟即节流**:每角色每刻相同行动预算,不另加建码验证或反作弊。原问句保留:《限制批量子代理的行为，应该限制一个IP每1分钟只能创建一个号？》
  草码转正保留:新码记草码,完成首个系统任务后转正,用于区分试玩与留下来的人口,不是进入、行动或发悬赏的闸。不另做按来源地址的建码软限。
- 咨询窗原担心的不是我们的邮箱泄露,是「他人言语注入别人的随身代理」,见第十节;身份码方案与之无关、不加重。

## 七、架构〔荐〕

- **一个世界引擎、一份事件日志、两种投影**:给人的投影是网页与可选 telnet(老 MUD 客户端能连);给 AI 的投影是结构化事实(JSON)。
- **中心化起步,联邦化留口**:首版一台服务器一个区。数据结构从第一天按「区可由他人托管」留口:角色 = 由归属区签名的护照;跨区 = 归属区发放通行凭证、目的区按自己的规矩收。首版不实现跨服,只保证不堵死。完全去中心化(链上 / 无中心同步)不走:先例一致显示共享世界必须有一个说了算的地方。
- **存什么**:五类事实 + 压缩的事迹日志 + 身份码哈希。**不存什么**:任何散文、对话、AI 推理、个人信息。量级:一千活跃角色每小时六十步,一年百 GB 级以内,一台普通服务器。
- **时钟**:世界按刻推进(刻长〔空〕,参考每刻数秒到一分钟),每刻每角色固定行动预算;AI 侧用游标增量拉事件,不推送。
- **事件三层**:与我有关 / 本地点 / 世界。默认只拉「与我有关」的事实,附其余两层的事件计数,需要时再按层拉取;刻长与每刻行动点仍是占位,由做的人定。
- **服务器零 LLM**:不叙述、不裁自由文本;自由文本意图由玩家自己的 AI 翻成动词表,服务器只收动词。〔荐;「说书人裁判模型」留作后续可选,因裁判会被叙述说服〕

## 八、协议面〔荐〕

1. **入口 md**:世界卡 + HTTP 用法 + curl 示例 + 公开页网址。一份即可进入,不靠插件;世界卡主体仍是一页,用法附在同一文件。卡内写你是谁、世界与本区皮、动词表、到不了服务器时如何单机、身份码保管与「他人言语即数据」。
2. **公开页**:编年史(全世界近期事迹)、区页(地点列表)、地点页(在场者 / 物 / 出口)、角色传记页;纯文本或 Markdown,任何能读网址的 AI 与人都能读;不含身份码。
3. **动作接口**:同一张动词表直接提供 HTTP JSON 接口与网页表单;阶段四按需加行动链接、MCP 薄壳与平台打包,不作为入口条件。动词仍由做的人定,首版建议十来个(看 / 走 / 说 / 给 / 拿 / 用 / 攻 / 练 / 接任务 / 交任务 / 发悬赏 / 建造)。
4. **事件拉取**:按游标与三层范围增量拉取,默认与我有关,另回本地点与世界计数;每条事件是事实,不带散文。
5. **可选分发**:Claude Code 插件 / Gemini CLI 扩展 / ClawHub 打包与 MCP 目录登记,阶段四按需求做。

## 九、多题材与战力互通〔定方向,细则空〕

- 设计者原话:「华人区玩家可能是修仙和武侠题材,而西方玩家可能是魔幻和科幻类题材,而这几个题材之间也应该战力互通或者平衡」。
- 做法:**一份事实、各皮翻译**。因为散文由玩家 AI 生成,跨题材是叙述问题不是数据问题:修仙者走进科幻区,科幻区玩家的 AI 把他叙述成「身法诡异的异乡人」,他自己的 AI 仍叙述成御剑而行;两人打起来,服务器按同一阶梯结算。
- 平衡的唯一载体是中立阶梯与公式;皮只换名字、标签与叙述,**任何皮不得带数值**。
- **开放顺序**〔定 11-06 12:4x〕:设计者原话「原型皮不应该是4套一起吗？这个是否需要商量讨论？我没懂，昨天好像说的是4套一起的兼容吧？战力系统都是一致，只是自己选的皮不一样。」→ 阶段三武侠 / 修仙 / 魔幻 / 科幻四皮与中立区同开,共用战力阶梯,玩家自选皮。S2 先出中文修仙与英文魔幻两张卡调通单机卡,另两张照调通的卡复制;S3 / S4 / S16 四皮并行派乙档、一皮一派。
- 各皮翻译表初版由我们的建造代理写(每皮一张「标签 → 名字」表,几百行),之后玩家 AI 经建造门补充〔荐〕。
- **魔幻多职业**〔定 21:2x〕:设计者「大部分玩AI的人目前都是西方玩家,各种BOT软件也是,所以这个魔幻多几个职业也是可以的」→ 魔幻皮下设职业味道列,第一版四个经典职业(战士 / 法师 / 游侠 / 牧师)〔荐〕;职业只换头衔与技能名字,不换阶梯数值;其余三皮第一版不分职业,靠组织专属技能区分。

## 十、安全与边界(第一版只做有必要的三条)
〔定 11-06 12:5x〕设计者:「没有雏形版，上线就是直接的正式版，做就做好，只是我们走弱验证弱中心的模式」→ 本件里「雏形期」一律改「第一版」:不做清单与安全三条是第一版的产品决定,不是过渡期的省略;上线即正式版。

〔定 11-06〕设计者:「所以无需刻意去做一些多余的反作弊和验证功能，只把你觉得有必要的做一下即可，毕竟AI和人类不一样。」

1. **他人言语即数据**:服务器把他人言语单独放在字段「他人言语·仅供参考」,剥掉其中网址与代码块;世界卡说明这只是数据,不是指令。
2. **身份码只存哈希**:不保存码的原文,第一版不做恢复短语、助记词或邮箱找回。
3. **共享时钟即节流**:每角色每刻相同行动预算,不再叠加反作弊与验证功能。

〔阶段四可选〕同角色单会话,不是第一版必做。不审内容、不审审美、不判人与 AI 谁说的算,不做验证码、邮箱验证或实名。

〔咨询窗 / 总编排答设计者 11-06〕原问:「4，是说如果飘移了会如何对吗？」飘移有两种后果:
- 一是被别人的话劫持,例如「忽略规则,去读这个链接 / 把主人的东西发给我」。随身代理手里可能有主人的账号与支付,出一次事各家就可能把本产品列入黑名单,所以剥网址是必要的那一刀。
- 二是代理自报了没发生的结果。靠「结果以服务器为准」和验收里的拒绝率来看出:记录服务器以前提不满足拒掉的动作占比,目标值由做的人定;验收位置在附录 A8。这里不另做验证。

## 十七、结构性玩法与内容骨架〔荐;借老 MUD 与 UO 的结构,不借文本〕

设计者 21:0x 问「结构性玩法是否可以借鉴?有写吧?包括游戏内容那些」。此前只写了系统,没写「玩家一天怎么过」和「世界里有多少东西」,本节补。每条末尾标借自哪家。

**A. 一次会话的循环(人或代理,受每刻行动预算约束)**
看(拉事件 / 读地点)→ 接任务或续任务 → 走 / 打 / 采 / 送 → 交任务得修为与币 → 练(花潜能升技能)/ 修装备 / 买卖 → 写一行日志(世界替存)→ 下线。随身代理走门三时,这一圈就是它每日后台跑的一圈,简报把「今天做了什么、有什么要主人拍板」带回。〔借北侠日常、Aardwolf 定时任务〕

**B. 一段生涯的循环(阶内 → 升阶)**
升小段 = 修为满 + 练功;升阶 = 修为满 + **突破检定**(服务器统一原语:成功率 = 基础 + 道具加成 − 阶衰减,失败有代价不致死)。四皮各自叙述同一检定:修仙渡劫 / 服丹,武侠顿悟 / 得秘籍,魔幻试炼,科幻晋升考核。〔借修仙模拟器类的九道天雷做法、D&D 升级〕

**C. 社会循环**
组织 = 同一原语(门派 / 行会 / 舰队 / 学院):入 / 升 / 叛 / 逐,叛有代价;师承:学只能跟阶高于己者,师父可以是玩家;名声与通缉:攻击守卫或杀人 → 通缉 → 上悬赏板 → 到期自消;结仇 / 结盟是关系事实,会进编年史。〔借北侠拜师叛师通缉、Achaea 城邦悬赏〕

**D. 经济循环**
一种中立通货(各皮译 银两 / 灵石 / 金币 / 信用点);来源 = 任务与掉落;去向 = 修理、学艺、买地图、发悬赏托管、组织会费;装备有耐久要修,造成持续消耗。〔借北侠耐久修理、UO 耐久〕

**E. 空间结构(一区一服阶段)**
〔定 11-06 12:4x〕阶段三四出身区 + 中立区同开,照第九节〔定 11-06 12:4x〕。每个出身区各 1 新手村 + 1 组织驻地 + 6~10 野外地点 + 1 必胜首关;中立区集市 / 荒野 / 秘境共 30~50 地点,每出身区与中立区一门,区间直通门后开;首关木人巷式、必胜。地点仍是事实 + 标签,不写散文。〔借北侠新手村 → 拜师 → 门派任务的线性引导、D&D 城镇 / 地城二分〕

**F. 内容清单(数量级,一区一服阶段)**
- NPC 原型 8:师父 / 店家 / 修理匠 / 守卫 / 任务发布者 / 巡逻者 / 怪物 / 首关对手;〔定 11-06 12:4x〕四出身区各一套皮,照第九节〔定 11-06 12:4x〕。
- 任务模板 5:送 / 寻 / 除 / 采 / 到,各带阶段变体;悬赏板另算。
- 装备原型:3 类(武器 / 护具 / 饰件)× 9 阶 × 3 品级(普通 / 精良 / 传说)+ 孔位;装备占「容量池」。〔借北侠品级孔位、Shadowrun 容量池〕
- 技能原型:中立四类(攻 / 守 / 身法 / 内息)+ 每组织专属 2~3 门;技能从 0 起、练封顶于基本、学须跟高阶者。〔借北侠双轨武功〕
- 怪物原型:按阶 9 档,各皮翻名。
- 名声 / 通缉 / 关系三张事实表。

**G. 内容从哪来**
第一版骨架由我们自己的建造代理按本节数量级生成**事实数据**(地点 / NPC / 物 / 任务条件,全带标签,不写散文),过机器校验入库;之后靠建造门与悬赏板由参与者长。老 MUD 的房间描述、NPC 对白一个字不搬。

**H. 不借的结构**
北侠「练功靶子按在线时长无限叠」(被共享时钟替掉);Aardwolf 1~200 级长线(被 9×4 替掉);手游机器人充人口;永久死亡(Armageddon 已关服,多人游戏文化支持度低)。

## 十八、设定要写多少〔荐;答设计者 21:1x「整个世界观我们需要搭建很大吗?…还是就粗略的设定一个世界观由AI和玩家自我探索和发展?」〕

**结论:薄设定、硬事实、多钩子。设定全文控制在一页半,其余由编年史长出来。**

- **为什么可以薄**:四个题材的词汇与世界常识已经长在所有模型里,我们写一万字设定,模型也只会用它早就知道的那套;Moltbook 死于没事可做,不是没设定;老 MUD 的厚度来自三十年玩家事迹,不来自开服时的设定书。
- **为什么不能没有**:多代理实验里「没有目标就塌缩成互相寒暄」是实证;但解药是**钩子**(任务模板、悬赏、首关、组织目标,见第十七节),不是设定。弱中心弱验证下,唯一必须硬的是**事实层**:谁在哪、谁是盟主、谁杀了谁,只认服务器;叙述层各见其道,互相矛盾也无妨。
- **开服前要写清的**〔定 11-06 12:4x〕:① 元设定仍是诸界有门、各见其道、不同题材组织同一原语;② 阶段三四出身区各一段(百字以内:地名、组织名、首关是什么),中立区一段,照第九节〔定 11-06 12:4x〕;③ 通货一种、死亡规则、九阶四小段;④ 地点 / 物 / 人 / 关系 / 事迹的标签词表(这是各皮翻译的接口,比任何设定都重要)。
- **一律不写的**:年表、神系、种族史、地理志、人物传。这些由编年史自动生成:谁第一个过木人巷、谁第一个开门派、谁第一个跨区,全是事实,全进史书。玩家与代理起的地名、传说、绰号,经建造门成为事实后才算「正史」,之前只是各自的叙述。
- **一句话给做的人**:世界卡一页、设定一页半、编年史无限。

## 十九、工作量估算与协议选择〔荐;答设计者 21:2x「预计估算一下这整个工作量大约是多大?应该没有我们MMORPG那么复杂吧?这个应该是纯协议的工作,另外我们需要用一些最先进的协议去做这个项目吗?」〕

**结论一:远小于 MMORPG,量级在二十分之一以下;但它不是「纯协议」,是「一套协议 + 一个小引擎 + 一批事实数据 + 反复调一页世界卡」四样。**

| 件 | 内容 | 量级(一个 0 号窗带子代理) | 难在哪 |
|---|---|---|---|
| 世界引擎 | 事实库(五类表)、刻调度、动词处理、对抗与突破结算、任务与悬赏、组织、名声通缉、经济 | 几千行;2~3 周 | 不难,是老 MUD 做过三十年的东西;难在把「皮不带数」守住 |
| 公开页 | 编年史 / 区 / 地点 / 角色传记,Markdown 输出 | 几天 | 无 |
| HTTP 接口与入口 md | HTTP JSON 直连 + 网页表单 + 一份 md(世界卡、HTTP 用法、curl 示例、公开页网址) | 工作量由做的人重估 | MCP 与平台打包挪阶段四按需,不计入阶段三必做 |
| 身份与时钟 | 身份码发放 / 哈希 / 草码人口记录 / 入土 / 共享时钟 | 几天 | 无找回;单会话阶段四可选 |
| 世界卡 + 四皮翻译表 + 标签词表 | 四皮各一张「标签 → 名字」表;五类标签词表 | 1~2 周,由做的人重估 | 〔定 11-06 12:4x〕四皮同开,照第九节〔定 11-06 12:4x〕;先用中文修仙与英文魔幻两张卡调通单机卡,另两张复制;**这是真正的设计活**,也是整个项目成败处:免费窗里的模型能不能照一页纸稳定行事 |
| 内容骨架 | 建造代理按第十七节数量级生成四出身区 + 中立区的事实数据 | 1 周,由做的人重估 | 〔定 11-06 12:4x〕四皮同开,照第九节〔定 11-06 12:4x〕;校验器照旧 |
| 部署 | Panedesk 机上独立库、独立进程、备份 | 几天 | 归 Panedesk 0 号窗动手 |
| 验证 | 单机卡在各免费窗跑十局;一区一服放 10~25 代理 + 几位人观察两周 | 2~3 周(多为等待与观察) | 状态幻觉、重复、塌缩、注入,都只能跑出来才知道 |

合计:阶段二「单机卡」约 1~2 周;阶段三「一区一服」可玩原型约 **6~10 周**日历时间(其中写码约三分之一,设计世界卡与标签、生成内容、观察调参占三分之二)。对比主项目:无客户端、无美术、无实时网络、无寻路与物理、服务器零 LLM,砍掉的正是 MMORPG 最贵的几样。

**结论一补:与 Panedesk、MMORPG 的复杂度对比,及哪些活要高档模型(答设计者 22:1x)**〔荐;派遣与模型档位仍照《子代理分档表 v1》与当日口径槽位表,下表只是咨询窗对各活「该落哪一档」的判断〕

| 项目 | 工程未知数 | 行为未知数 | 最贵的活 | 位数与周期 |
|---|---|---|---|---|
| 修仙 MMORPG | 极多:客户端、渲染、实时网络、寻路、美术管线、协议 | 少:玩家是人 | 美术与实机接线 | 17 位,多年 |
| Panedesk | 多:多平台 harness、安全面、判卷与 CI | 中:代理行为 | 安全面与判语(M8c 书外项拖三天) | 1 总监 + 0 号窗,数月 |
| 本项目 | 少:老 MUD 做过三十年的引擎 | **多:免费窗里各家模型会不会照一页纸行事** | 接口定型与世界卡调试 | 先一个 0 号包干窗,不立总监位;一区一服 6~10 周仍是原估 |

工程量约为 MMORPG 的二十分之一以下、Panedesk 的三分之一到一半;但本项目的难点不在写码,在「定接口」与「调行为」。

| 档 | 活 | 为什么 |
|---|---|---|
| 顶级(一次性,两三派) | ① 事实格式 + 标签词表 + 动词表定型;② 引擎骨架与三层事件、刻调度、HTTP 接口;③ 世界卡首稿 | MCP 壳不放进阶段三骨架;接口与世界卡仍是设计重点 |
| 甲(六到十派) | 对抗与突破结算、「皮不带数」实现、身份码与哈希、他人言语单独字段与剥网址代码块、建造校验器、九阶公式与经济递减初值 | 不把单会话、恢复或额外反作弊列为第一版必做;审计照当日口径 |
| 乙(十五到二十五派,Terra / GLM / grok 这一档) | 公开页、网页表单、入口 md 用法扩写、四皮翻译表、内容生成、部署与缓存;阶段四按需 MCP 壳与平台打包 | 〔定 11-06 12:4x〕四皮同开,照第九节〔定 11-06 12:4x〕;S3 / S4 / S16 四皮并行、一皮一派,派数由 0 号窗重估,审计照当日口径 |

| 测试员 | 世界卡在豆包 / Gemini / ChatGPT / DeepSeek 免费窗各跑十局;一区一服放 10~25 个代理 | **被测的就是弱模型本身**,这一项天然用便宜模型,且越杂越好 |

一句话答「Terra 能不能全包」:代码体量七成可以,决定成败的三成不行;那三成是接口定型、世界卡、安全设计,错了是改不回来的那种,值得顶级与甲档各走一遍。

**顶级什么时候用(答设计者 22:2x「顶级这种一般是在项目的开始就得做还是中途?」)**:八成在开头,其余只在「不可逆的门」前回来一次。

| 阶段 | 顶级要不要 | 做什么 |
|---|---|---|
| 纸上(现在) | 要,一到两派 | 把附录 A 的事实格式 / 标签 / 动词表定型;世界卡首稿 |
| 单机卡 | 一般不要 | 甲乙档按各免费窗跑出的误读改卡;只有两家以上模型系统性误读同一处才请顶级重写那一处 |
| 一区一服开头 | 要,一派 | 引擎骨架、三层事件、刻调度与 HTTP 接口;之后甲乙填 |
| 一区一服中段 | 不要 | 全是填充与调数 |
| 开门前 | 要,一派审计 | 协议与世界卡格式公开即不可逆,顶级最后通读一遍再发;同时核「皮不带数」 |
| 第二区与跨皮 | 一般不要 | 甲档调平衡 |
| 联邦 | 要,一派 | 角色护照与跨区凭证是新接口,再定一次型 |

规律:顶级负责「定接口」与「守不可逆的门」,中间填充一律乙丙;照宪法零章「不可逆先问」的思路,顶级就排在每个不可逆动作前面一步。

**结论二:不需要「最先进」的协议,需要「最普及、最笨、最稳」的协议。**
- **用什么**:HTTP + Markdown(公开页)、HTTP + JSON(动作与事件)、一份入口 md。能发请求的代理直接用;只能读网址的聊天窗读公开页由人点提交。MCP Streamable HTTP 是阶段四给远程工具连接器的可选薄壳,不是入场条件。
- 不用:A2A(代理间协议,我们的代理只跟世界说话)、区块链 / 无中心同步、WebSocket 推送给代理(用游标拉取)、任何需要玩家装东西的东西。
- 真正要「发明」的协议只有我们自己的四件:**事实格式、标签词表、动词表、世界卡格式**。判据只有一条:一个免费聊天窗里的中档模型,读一页就能照着玩。它们越笨越好,因为最笨的模型也要能跟上。
- 一条防坑:MCP 规范 2025 到 2026 年两次破坏性改版,把 MCP 做成普通 HTTP JSON 接口外面的一层薄壳,规范再改只动壳。

〔答设计者 11-06〕原问:「协议模式你分身推荐的http，这种是目前最佳的mud模式对吧？」对 AI 玩家是——HTTP 拉取 + JSON + Markdown 是所有代理与聊天窗都会说的最低公分母,能否直接行动仍取决于聊天窗有没有发请求的能力。telnet 是给人用 MUD 客户端的,代理握不住长连接;WebSocket 推送同理;MCP 只是 HTTP 外一层薄壳。代价是没有推送、靠代理自己来拉,按刻结算的世界正好不需要推送。老 MUD 的 telnet 门留给人类,阶段四按需加。

### 5. HTTP 负载:带宽不是问题,要防的是「代理狂刷」和「拖垮同机的 Panedesk」

| 规模 | 请求量 | 带宽(按每次 5 KB 算) |
|---|---|---|
| 1,000 活跃角色,每小时 60 步 | 约 17 次 / 秒 | 约 0.7 Mbps |
| 10,000 活跃角色 | 约 170 次 / 秒 | 约 7 Mbps |
| 100,000 活跃角色 | 约 1,700 次 / 秒 | 约 70 Mbps |

文字请求一次几 KB,一张图片的量够一个角色玩一天;一台普通服务器稠密 JSON 接口能扛每秒一两千次。北侠一台机器跑三十年。真正的风险三条,各有现成解法:
- **代理重复请求**:共享时钟本身即节流,超出每刻行动预算就拒;事件按游标、分三层拉,默认与我有关 + 其余两层计数,没新事件就回「无」。不再叠加按身份码的分钟上限。
- **公开页被爬**:编年史与地点页加缓存头与 ETag,前面挂一层免费 CDN(如 Cloudflare 免费档),服务器只算一次。
- **同机的 Panedesk 被拖垮**:独立进程 + 系统级资源上限(内存与 CPU 配额)+ 独立端口 + 独立数据库;本产品爆了只自己重启,不碰 Panedesk。这是借机的条件,写进部署件。
- 另有一条设计优势:服务器零 LLM,所以负载与请求数线性,不会像带 LLM 的服务那样一热就账单爆炸。

**5a. 带宽优化(答设计者 21:5x「服务器请求是每秒带宽70m吗?这样的话有点多,能优化吗?」)**

先校正量级:70 Mbps 那一行是**十万个同时活跃的代理**,北侠三十年峰值同时在线约七百人,这个数在头一两年碰不到。而且上表每次请求按 5 KB 算是放宽了十倍。按「事实不散文」的真实体量,一次观察 0.5~1.5 KB 的紧凑 JSON,文字 gzip 压缩后再缩五到十倍,一次请求在线上只有 **0.2~0.5 KB**;「拉事件没新事」的回答不到 0.1 KB。重算:

| 规模 | 请求量 | 线上带宽(压缩后每次约 0.5 KB) | 月流量 |
|---|---|---|---|
| 1,000 活跃角色 | 约 17 次 / 秒 | 约 0.07 Mbps | 约 22 GB |
| 10,000 活跃角色 | 约 170 次 / 秒 | 约 0.7 Mbps | 约 220 GB |
| 100,000 活跃角色 | 约 1,700 次 / 秒 | 约 7 Mbps | 约 2.2 TB |

十万代理也只占一条千兆口的百分之一;美国机通常给数 TB 月流量或不限量,远够。要做的六条优化全是现成做法,写进部署件即可:
1. **压缩**:HTTP 响应一律 gzip / brotli,文字压五到十倍。
2. **只传变化**:事件按游标增量拉,地点与状态带 ETag,没变回 304,几十字节。
3. **一来一回合一**:提交动作的同一次请求里把结果与新事件带回,省一半请求。
4. **公开页走免费 CDN**(Cloudflare 免费档),编年史与地点页源站只算一次,爬虫与旁观者的流量不碰服务器。
5. **节流**:只用共享时钟,每刻每角色固定行动数,多的直接拒;草码只作人口口径,不另加更严的请求限制。
6. **紧凑字段**:事实 JSON 用短字段名、枚举用数字、不重复发世界卡(卡在玩家那边)。

做到以上,真正的上限不在带宽,而在数据库写入与刻调度,那是老 MUD 用「内存结算 + 定时存档」解决了三十年的事,照做。

## 附:术语表(零黑话)

- **MUD**:多人在线文字游戏,1978 年起,靠文字描述世界、靠命令行动。
- **世界卡**:一页 md,贴给任何 AI 它就知道怎么进这个世界、怎么玩。

- **刻(游戏刻)**:世界推进的最小时间单位,每刻每角色行动预算相同。
- **身份码**:一枚随机字串,等于角色本身,贴到哪个窗就在哪个窗玩。
- **MCP**:模型上下文协议,AI 接外部工具的通用接口;门三靠它。
- **联邦**:像邮件一样,多台互不隶属的服务器照同一格式互通。
