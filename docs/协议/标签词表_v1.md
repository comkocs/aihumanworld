# 标签词表 v1

## 1. 用法与闭合集合

英文键是协议，中立释义解释事实，不提供某皮的战力。表中**每一行是一枚键**；范围型分面另逐枚列出。未登记键不得作为既有键的别名混入数据；新增同义名称放翻译表，不扩充事实枚举。实体 ID、content_key、组织专属技能标识不是偷偷扩大的通用标签全集，只能使用第 8 节给定的扩展槽。

五类事实为地点、物、人、关系、事迹；任务、技能、组织、名声及通缉是五类事实的结构细分，附属键也在本件列全。生命周期、任务状态、HTTP 操作、事件类型是《事实格式_v1》《动词表_v1》的封闭协议枚举，不另伪装成题材标签。数据字段存裸枚举（如 kind=`blade`），翻译查找使用带命名空间键（如 `item.blade`），避免 `guard`（守卫／技能）与 `water`（地点／元素）碰撞。

## 4. 人的全集

`kind` 描述参与身份，`body` 描述形态，`archetype` 描述 NPC 职责；三者不能混成一个 tags 数组，也不能按模型推断人机。NPC 必须且只能有一个主原型；需要店家又能修理时用中立服务动作的规则配置，不另添加“复合人种”。

## 8. 组合键规范（不是任意标签拼接）

分隔符固定为 Unicode 中点 `·`（U+00B7），前后不得有空格。段内 ASCII 小写；禁止全角点、短横线冒充中点。对象 ID 不进入通用组合键。读入时按字段类型生成键，不接受自由顺序的 tags[]；重复分面、缺失必填分面、未知分面和串错领域均是 `INVALID_KEY`。

### 8.1 完整事实签名

| 对象 | 唯一顺序与必填分面 |
|---|---|
| 物定义 | `item.<kind>·tierN·gradeN·element.<element>`；四段全有，none 也写出。category 从 kind 派生，slots 属数值不进入签名。 |
| 地点 | `place.<kind>·tierN·danger.<danger>·combat.<combat>`，后接所有 `feature.<feature>`，按 ASCII 升序；无 feature 则无后缀。region 与出口是事实字段，仍需同时返回，不能从皮名猜。 |
| NPC | `person.npc·body.<body>·npc.<archetype>·tierN·stageN`。 |
| 玩家／官方 | `person.player` 或 `person.official` + `·body.<body>·tierN·stageN`；无 NPC 原型段。 |
| 关系 | `bond.<kind>`；方向和具体端点由 bond 字段给出，不用拼入翻译键。 |
| 事迹 | `deed.<kind>`；胜负、对象与差量由 deed 字段给出。 |
| 基础技能 | `skill.<base>`。 |
| 组织技能 | `skill.org·skill.<base>·content.<realm>.<org_local>.<skill_local>`。 |
| 任务模板 | `task.<tpl>·tierN·stageN`；具体条件与奖励不写进皮。 |

物与地点的签名只唯一确定**分类**，不编码全部规则字段：例如 potion 的恢复／突破用途看 definition.effect，钥匙目标看出口 key_def；API 必须一并返回定义，不能凭短名猜用途。签名不保证唯一实体：两个同签名地点用 id 区分，不能把“同类”当“同一个房间”。两件同类物有不同耐久、孔位或持有者时仍分别按实例 ID 操作。“无歧义落点”指名字在给定示例的事实描述下唯一归类，不承诺仅靠自然语言名字猜到全部事实。

A2 的 `blade·tier3` 不是 v1 可入库的完整键。迁移为 `item.blade·tier3·grade1·element.none`（grade1、none 必须由原事实确认，不能凭旧短键自动补）。`item.blade·tier3` 仅是**展示短名候选键**；展示必须另外补出品级与元素，不会丢弃这两个事实。类似地 `water` 必须改写成 `place.water` 或 `element.water`，`guard` 必须指明 `npc.guard`、`skill.guard`、`stat.guard` 或实际字段，不接受含糊别名。

### 8.2 翻译查找与组合（S3 直接照做）

翻译命中优先级固定，不允许模糊相似匹配：

1. 若表有完整事实签名的行，使用其 name；完整签名覆盖所有分面，不再重复补词。
2. 物无完整行时先试 `item.<kind>·tierN`；命中后补上 `gradeN` 的 name 和非 none 的 `element.<element>` 的 name。仍未命中则分别取主键、tierN、gradeN、非 none 元素，以中文顿号连接供上层自然表达。任何一项缺失，保留原键并标 `translation_missing`，禁止猜成近义的别类。
3. 地点无完整行时使用 `place.<kind>` 名，附 tier、danger、combat 及有序 features 的独立翻译值；页面可分列，不强行揉成一句长地名。所有分面仍回原键，不能用一个“安全村”覆盖实际 pk 字段。
4. 人默认按主键／body／archetype／tier／stage 分列；职业只参与下一款展示覆盖。关系和事迹直接查唯一主键。任务按主键加 tier、stage 组合；组织专属技能先查 content 完整键，未命中显示 skill.org + base 名与内容 ID，不把未知技能猜成另一个技能。
5. fantasy 的职业覆盖仅允许 `title·tierN·class.<class>`（角色头衔）及 `skill.<base>·class.<class>`（四类技能名）。未填覆盖时回通用 tierN 或 skill.<base>。其他三皮 class 必须 null，不出现覆盖行。职业不能覆盖物、条件、费用、属性、掉落或公式。
6. NPC 的默认展示组合可由四皮独立起名；不将 default skin 强加给观察者。中立区按观察者所选皮展示同一份事实，所有 ID 和中立数值原样返回。

### 8.3 允许的内容扩展槽

- `content.<realm>.<type>.<local>`：S16／建造生成的内容标识对应展示名称；type 仅 `place/item/task/org/skill`，各段 ASCII 小写字母数字下划线。实体的 content_key 必须采用该形状，例如 `content.r1.place.market`；实例使用 ID，不另造展示内容键。
- 组织技能特例沿 8.1 的 `content.<realm>.<org_local>.<skill_local>`，以 `skill.org` 前缀限定，不与普通 content 槽混用。
- `org_rank.<local>`：组织 ranks 中声明的职级展示名；不带战力公式。默认 member 已列出，新增 local 仅用于该组织实际登记的 rank，不能冒充新的通用键。
- content 名只在展示资产中登记。建造事实只提交内容键，若 S3 暂无名则显示键，不由服务器 LLM 补文案。内容名称不重名的机器判据为同一 realm/type 的 content_key 唯一，不做跨语言同音／审美审查。相同显示名可以指不同实例，操作仍用 ID。

## 9. 翻译表文件格式定稿

S3 每皮一份 UTF-8 无 BOM 的 JSON 对象（文件位置由 S3 派单定，不在本单建），结构如下；示例只演示格式，不是 S3 全表：

```json
{"schema":"aihw.translation.v1","skin":"xiuxian","locale":"zh-CN","entries":[{"key":"item.blade","name":"刃兵","flavor":null},{"key":"item.blade·tier3","name":"青钢剑","flavor":"锋刃映着冷光。"},{"key":"grade1","name":"普通","flavor":null},{"key":"element.none","name":"无元素","flavor":null},{"key":"tier3","name":"金丹","flavor":null}]}
```

| 字段 | 类型与约束 |
|---|---|
| schema | 必填常量 `aihw.translation.v1`，格式版本，不是游戏数值。 |
| skin | 必填四皮枚举之一，neutral 不可用。 |
| locale | 必填语言标识，当前每文件一种；魔幻中英可各用一份同 schema 数据或各自交付，由 S3 派单定，不在单个 name 混拼双语猜语言。 |
| entries | 必填数组；key 唯一，无未登记键；顺序不影响语义。 |
| entries[].key | 必填原子键、8.1 完整签名、8.2 明列的短名／职业覆盖或已登记内容扩展槽。 |
| entries[].name | 必填非空展示名，不得含属性表、脚本、公式、网址或代码块。 |
| entries[].flavor | 必填、可 null；有值只能一句风味，不承诺任何额外数值效果。 |

**皮不带数**：不得增加 power、cost、multiplier、chance、level 等数值字段；不得在 flavor 藏“额外伤害”“成功率提升”等规则。tier3、grade2 出现在 key 是指向中立事实，不是皮内数值。数值始终读取事实和 S5 规则。

S3 四皮均须覆盖本件所有固定原子键；不是要求穷举全部笛卡尔积。9×4 阶段用 tier 和 stage 原子组成，装备 3×9×3 用分类／阶／品级原子组成，八 NPC × 四皮用同一八键翻译，不为皮分叉 NPC 原型。短名／完整签名可按内容逐条补，缺少短名不能阻断基础组合。所有 entries 只含 `key/name/flavor`，不在翻译表写服务器事实、条件、掉落、效果或角色分类。
