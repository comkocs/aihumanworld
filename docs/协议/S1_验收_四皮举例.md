# S1 验收：四皮举例

## 1. 验收口径

本单只做一次纸面验收，不写代码、不运行测试、不跑 build。以下四皮各 20 行，其中物 10 行、地点 10 行，共 80 行；表内名称是说明归类的临时展示例，不替 S3 交付正式翻译全表，不落入服务器事实库。名字不能反推未声明属性，以下完整键组合就是该行的中立事实定义；同类实例仍凭 ID 区分。阶、品级为既定结构档位，示例不规定战力／收益终值。

每行按《标签词表_v1》§8 的固定顺序：物为 kind→tier→grade→element；地点为 kind→tier→danger→combat→按 ASCII 排序的 feature。括号只说明展示名字，不另增属性。四皮可以指向相同键组合，这证明皮换名而非换数；中立区仍用观察者四皮之一显示，并非第五份词表。

## 6. 一次纸面验收记录

### 6.1 三项结果

1. **80 行归类通过**：四表各 20 行，物各 10、地点各 10；完整签名按固定顺序，每行均为已登记主键和分面，无歧义。初稿消歧是命名空间、物品级／元素完整性、危险度与战斗模式拆分、NPC 三分面、师承方向与装备三大类，已在词表 §10 记明；没有另起一轮全量测试。
2. **动词上限通过**：包含 enter 共 16 个；tell 合并进 say(target)，没有“16 个之外再加 enter”的计数漏洞。use 的封闭 op 为该动词参数，不是另一个 HTTP 动词；其分支已逐项列前提和效果，不能扩展为任意指令。
3. **产品十七节 F 覆盖通过**：逐项映射如下，未把数量级当最终数值。

| 产品内容 | 词表落点与事实承接 |
|---|---|
| NPC 八原型 | `npc.master/merchant/repairer/guard/quest_giver/patroller/monster/tutorial_opponent`；char.archetype，四皮复用同一八键。 |
| 任务五模板 | `task.deliver/find/slay/gather/reach`；task template 的 tier/stage 阶段变体，instance 条件均可服务器核实。 |
