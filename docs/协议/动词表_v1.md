# 动词表 v1

## 1. 十六个动词与 HTTP 适用域

完整动词集合固定为：`enter / look / events / whoami / go / say / take / give / use / attack / train / learn / task / bounty / build / breakthrough`，**共 16 个，包含首入发码**。将 A3 的 tell 合并为 say 的目标参数；use 容纳有明确判别字段的物／服务／关系操作，不接受任意脚本或自由意图。操作枚举也在本件封闭列出，不能借 use 执行未定义玩法。

- 通用动作入口：`POST /v1/actions/<verb>`，`Content-Type: application/json; charset=utf-8`；URL 只含版本和动词，不带身份码。所有普通动作（含读取）使用 JSON 请求体。GET 不执行动作；公开定义目录、公开页与网页薄壳见 §1.1，不额外增加动词。
- 通用动作与网页 JSON 的鉴权头：`Authorization: Bearer <身份码>`；实际码由首入返回，本文不出现原码示例。除 `enter {mode:"create"}` 外均必填；这两类入口的身份码不进请求体。传统 `/act` 表单的凭据正文例外仅见 §1.1；所有入口均不将码放入查询参数、日志或错误回显。
- `enter create` 只为普通 player 建档；official 和 npc 是开服导入，不是玩家可自报的类型。第一版无找回、单会话、验证码、建码限流、额外反作弊字段。
- 请求形状：`{"args":{...}}`；每个分支只接受定义的字段，缺项／未知字段／错误类型回 `INVALID_ARGUMENT`，不能接受客户端提交自己的结算结果。
- 成功响应：`{"protocol":"aihw.v1","ok":true,"tick":Tick,"rules_revision":Key,"ap":{"remaining":UInt,"per_tick":UInt,"next_tick":Tick},"result":object,"deed_ids":ID[],"event_head":Seq}`。
- 拒绝响应：`{"protocol":"aihw.v1","ok":false,"tick":Tick,"error":{"code":ErrorCode,"field":string|null,"details":object},"ap":object|null}`；未通过鉴权时 ap=null，不泄露角色。details 只允许本节错误表声明的结构字段，不能回显原码、原始附言或堆栈。协议格式损坏可 tick=null。
- 返回 result 的事实行、Changes、分页与投影全部沿《事实格式_v1》，私有 identity 永不返回；唯一例外是 enter create 的一次性 `identity_code` 输出，不属于事实行，也不持久记录。服务器重启或响应丢失后不能重发旧码，只能另建。
- 业务检定“失败”是 `ok=true,result.outcome="failure"`，仍可能消耗预算和资源；请求前提不满足是 ok=false，不耗游戏预算。不存在默认“网络重试不会重复执行”的承诺。

请求示例（无身份码值）：
```http
POST /v1/actions/go
Content-Type: application/json; charset=utf-8
Authorization: Bearer <身份码>

{"args":{"dir":"north"}}
```

响应示例（预算与示例时刻／序列仅演示；游戏数值占位）：
```json
{"protocol":"aihw.v1","ok":true,"tick":"8","rules_revision":"balance.v1","ap":{"remaining":2,"per_tick":3,"next_tick":"9"},"result":{"from":"r1:place:x1","to":"r1:place:p1","changes":[{"table":"char","id":"r1:char:c1","after":{"loc":"r1:place:p1"}}]},"deed_ids":["r1:deed:d1"],"event_head":"20"}
```

### 1.1 公开定义目录与网页薄壳

以下只是同一事实与十六动词的不同入口；动作仍经同一分发器、鉴权、预算和事务，不创建第二套玩法或会话。

| 路径与方法 | 鉴权／参数 | 返回与适用域 |
|---|---|---|
| `GET /v1/defs` | 无鉴权、无业务参数 | 公开定义目录，直接返回 `{items:ItemDefinition[],skills:SkillDefinition[],places:{id:ID,content_key:Key}[]}`，均为本 realm 完整数组、无分页；不套动作信封，不含物实例／已学行。用实例或已学行的 `def_id` 匹配相应数组的 `id`。三组分别读取，不承诺与动作或彼此同一事务快照。 |
| `GET /play/definitions` | 同上 | 与 `/v1/defs` 同内容的网页别名，不是唯一取定义路径。 |
| `GET /play` | 无鉴权、无业务参数 | HTML 网页入口；资源为 `GET /play/static/play.js`、`GET /play/static/play.css`，不执行游戏动作。 |
| `GET /play/lexicon/<skin>/<locale>.json` | 无鉴权；skin 为四皮，locale 为已有语言文件 | 返回《标签词表_v1》§9 的翻译 JSON（`schema/skin/locale/entries`），无动作信封；未知皮／语言文件返回 404。选择页面翻译不改变角色出身。 |
| `POST /play/v1/<verb>` | JSON 请求 `{args:{...}}`，Bearer 规则同通用动作；入口为 `door:web` | 正常成功／业务拒绝同 §1 信封；`enter` 提供 door 时须为 web。只有本节下述 look 扩展不同。 |
| `GET /act`、`GET /act/<slug>` | 无鉴权；可选 `skin/locale` 只选翻译 | HTML 表单目录／单表单，不执行动作。slug 来自目录，支持小写字母、数字、短横线及下划线，包括 `use-org_join/use-org_leave/use-relation_end/use-relation_accept`。只覆盖已有表单分支，其余使用 JSON。 |
| `POST /act/<slug>` | `application/x-www-form-urlencoded`；除 enter-create 外在正文 `code` 字段携码，不取 Bearer 作为表单凭据 | 表单固定分支与字段转为 `{args:{...}}` 后经同一分发器，以 `door:web` 执行；响应为 HTML 结果页，内含动作信封 JSON，HTTP 状态沿分发结果，不是裸 JSON。可选空字段省略、字面量 `null` 转空值；`code` 不进入 args。 |

网页 JSON 的 look 仅在**原始请求显式写 `args.section:"place"` 且动作成功**时追加 `result.people:PublicRow<char>[]` 与 `result.items:ItemInstance[]`：people 为回包地点内 `state != buried` 的公开角色，items 为该地点持有且 available 的物实例。两组无分页，不受 limit 控制；基础 rows/page/counts 等不变。省略 section 虽默认 place，**不追加**两组；通用 `/v1/actions/look` 和 `/act/look` 也不追加。扩展在基础动作事务提交后分别查询，不保证两组彼此、或与基础 place/counts/tick/event_head 同一时点，不能当成原子快照。

网页 JSON 入口 Content-Type 不是 application/json 时 HTTP 415、JSON 无法解析时 HTTP 400，均只回 `{"ok":false,"error":{"code":"INVALID_ARGUMENT"}}`，没有 protocol/tick/ap/field/details；解析成功后的参数／业务错误才用 §1 完整信封。表单类型错误为 HTTP 415 纯文本，已知超大表单体为 HTTP 400 纯文本；未知页面／表单为 HTTP 404 纯文本，不强套动作错误封套。

公开事实页 `GET /`、`/chronicle`、`/region/<region>`、`/place/<id>`、`/char/<id>` 无鉴权，默认 Markdown，Accept 请求 HTML 时为 HTML；可选 `skin/locale` 仅选展示。它们不是本人私有读取接口。公开页按 ID 展示的列表取末尾数字（无则 0）再按 ID 字节序，事迹按 seq；不等同 §2 动作分页排序，也不保证命名 ID 的真实创建顺序。

## 2. 参数约定、预算与读取分页

类型 ID、UInt、Tick、Seq、Key、Tier、Stage、Holder、Condition、Reward 等见事实格式。`可选`表示请求可不传，给出默认值；`可空`表示允许 JSON null；二者不同。所有未写可选的请求参数必填。数值约束属于资源和类型一致性，不加身份或反作弊验证。

**数值以 S5《数值表_v1》及当前装载规则为准，下文“占位”是初稿来源标记，不覆盖现行值。** 读取及 enter、task list 为 0；attack/breakthrough 为 2；其余修改操作为 1；每刻 3 点、60 秒一刻。在办任务／未结悬赏／孔位上限现行为 3／3／3，旧 1／1／4 不再是现行值。日／周按刻日历：`day_index = floor(tick / 1440)`、`week_index = floor(tick / 10080)`，不按 UTC 跨日。读不耗点是接口语义（不是另加免费请求限额），实现不得给 look/events/whoami 加每分钟上限。所有 use 分支都使用收费键 `use`；say 定向／本地都用 `say`。`ap_costs` 的完整键为 `enter/look/events/whoami/go/say/take/give/use/attack/train/learn/task.list/task.accept/task.submit/task.abandon/bounty.post/bounty.cancel/build/breakthrough`。train start/stop 都用 train；look 因首探产生事实仍为 0。

读取分页统一 `Page = {after:ID|null,through:Seq|null}`：page 可省略但不可为 null；两个子字段均可分别省略，缺省各为 null。`limit:UInt|null` 可选，省略或 null 均取 world.rules.page_size，非空须为正整数；列表分支再校验不超过装载 page_size、through 不超过当前 deed_head（否则 INVALID_ARGUMENT）。首请求 through=null 时固定当前 deed_head；返回 `{rows:[],page:{after,through},has_more:bool,snapshot_changed:bool}`。列表是以当前事实为准的弱一致分页，through 标明扫描起点而非历史快照；后页 through 与当前 deed_head 不同则 snapshot_changed=true，必要时从头重取，不承诺捕获所有无事迹的库存维护。事迹列表另限制 seq≤through；其他事实仍取当前行，不建立服务端会话。

非 events 动作列表按 `(length(id), id COLLATE "C")` 升序，after 用同一二元键比较。仅同 realm/type、同固定字母前缀的数字分配 ID 等价数字自然序（如 d2 在 d10 前），不承诺全部事实按真实创建时间排序；种子／导入命名 ID 仍按长度再字节序，不另猜创建时序。公开页排序另见 §1.1。

`look(section=place)`／`whoami(section=char)`（含省略 section 的默认分支）仍校验 page/limit 的形状与类型，但不使用分页：不会执行 limit≤page_size 或 through≤deed_head 的列表校验；即使这两个上界超出也不因此拒绝。返回 rows=[]、page={after:null,through:当前 deed_head}、has_more=false、snapshot_changed=false。events 的 limit 同样可省略／可 null，取 page_size 且校验上界；游标按专用序列语义，不使用 Page。

默认本人状态 draft/active、life=alive 才能执行付费游戏动作；dormant/buried 通过 enter resume 处理。whoami/events 可以用于查询持码角色，不自动复活入土人口；look 需已在世界中（draft/active），死亡时可读现场，不可出手。成功鉴权请求更新 char.seen_at/last_seen_tick，不让普通读取代替 enter 的状态恢复；生命周期先按旧 last_seen_tick 判定，再更新访问时刻。

每个响应的 ap 按同一事务 tick 计算；预算不足给 `AP_EXHAUSTED` 和 next_tick，不替玩家排队。两窗持同码并发按同一预算原子结算，不顶会话。没有点数的被拒动作不产 deed/event，也不改条件进度。

## 3. 通用错误全集

HTTP 400 对格式错误，401 对鉴权失败，403 对事实不允许，404 对不存在或不可见，409 对当前事实冲突，410 对过期游标／不可继续身份，501 对未实现处理器的防御错误，503 对规则未装载或暂时无法确认事务提交。业务不足不回 429，不另立限速。下表 code 是唯一可返回枚举，各动词可用集合见后文。

| code | HTTP | 含义与 details 允许字段 |
|---|---|---|
| INVALID_ARGUMENT | 400 | 参数缺失、类型、范围、字段、分支错误；`expected:string`（固定类型描述，不含用户输入）。 |
| INVALID_KEY | 400 | 标签／组合键不合法；`expected:string`。 |
| UNKNOWN_VERB | 404 | 路径动词未登记；details 空对象。 |
| AUTH_REQUIRED | 401 | 缺少身份码请求头；details 空对象。 |
| AUTH_INVALID | 401 | 码不能对应可用哈希，统一拒绝不透露存在性；details 空对象。 |
| STATE_BLOCKED | 409 | 角色人口状态不允许该操作；`state,required_action:"enter"`。 |
| LIFE_BLOCKED | 409 | 死亡期间不可动作；`revive_tick:Tick`。 |
| IDENTITY_EXPIRED | 410 | 持有有效哈希但已超可恢复期限；`can_create:true`；凭据已清除则只回 AUTH_INVALID。 |
| RULES_UNSET | 503 | 所需规则槽尚未填；`rule_key:Key`。 |
| AP_EXHAUSTED | 409 | 本刻预算不够；`remaining:UInt,required:UInt,next_tick:Tick`。 |
| NOT_FOUND | 404 | 引用不存在或对调用者不可见；details 空对象，不区分两者。 |
| NOT_HERE | 409 | 对象不在当前地点；details 空对象，不泄露实际远处位置。 |
| NOT_ALLOWED | 403 | 模式、归属、组织职级或改宗前提不允许；`reason:combat/ownership/rank/registry/service/faith_locked/org`，改宗两项沿 §4.1。 |
| EXIT_BLOCKED | 409 | 出口锁闭或守卫阻拦；`reason:locked/guard`。 |
| INSUFFICIENT_RESOURCE | 409 | 币、潜能、物、体力不足；`resource:coin/potential/item/vigor,required:UInt,available:UInt`。 |
| CAPACITY_EXCEEDED | 409 | 装备容量超限；`required:UInt,available:UInt`。 |
| ITEM_STATE | 409 | 物已消耗、装备中、孔位状态不符或不适用；`reason:consumed/equipped/socket/type/durability`。 |
| SKILL_CAP | 409 | 练习达到技能上限；`level:UInt,cap:UInt`。 |
| TEACHER_REQUIRED | 409 | 无更高阶、更高技能教师或支付／师承不满足；`reason:tier/level/bond/payment`。 |
| TASK_STATE | 409 | 任务状态不允许本操作；`state:TaskState`。 |
| TASK_LIMIT | 409 | 在办任务或未结悬赏达到占位上限；`kind:accepted/bounty,limit:UInt`。 |
| CONDITION_UNMET | 409 | 可核任务条件或成长条件尚未满足；`reason:task/xp/stage/tier/location/training/rank/relation`。 |
| DUPLICATE_KEY | 409 | 相同域已有该 content_key；`table:place/item/task`。 |
| BUILD_INVALID | 400 | 建造格式／引用／阶内数值不合法；`reason:shape/reference/tier/name,field:string`。 |
| INVALID_CURSOR | 400 | 事件 cursor 非规范或大于当前 head；details 空对象。 |
| CURSOR_CONTEXT | 409 | 地点游标绑错地点；`place_id:ID,resume_cursor:Seq`。 |
| CURSOR_EXPIRED | 410 | 所请求段已压缩；`scope:self/place/world,resume_cursor:Seq,resync_required:true`。 |
| OFFER_STATE | 409 | 关系提议过期、已使用或确认人不符；`reason:expired/used/recipient`。 |
| RETRY_LATER | 503 | 确知事务未提交时 details 为 `committed:false`，客户端可重试；无法确定是否已提交时 details 为空对象，不填 committed:false，应先查事实。 |
| NOT_IMPLEMENTED | 501 | 无处理器时的防御错误，details 空对象；十六动词现均已实现。 |

所有动词共享 `INVALID_ARGUMENT/AUTH_REQUIRED/AUTH_INVALID/NOT_FOUND/RULES_UNSET/RETRY_LATER`；create 不要求 AUTH_REQUIRED，lookup 无外键时不必用 NOT_FOUND。所有付费游戏动作还共享 `STATE_BLOCKED/LIFE_BLOCKED/AP_EXHAUSTED`。后文“拒绝”仅列在共享集合之外的适用码；没有该条件的动词不得随意借用别的错误。

## 4. 逐动词定义

### 4.1 `enter` —— 发码与持码继续

- 参数：`mode:create/resume`。create 必填 `skin:Skin,door:api/web`，可选 `class:四职业|null` 默认 null、`model:string|null` 默认 null；resume 可选 skin/class/door/model，不传保留旧值（离开 fantasy 时 class 清空除外）。**阵营即出身皮，不另设任意更换的角色展示皮**：resume 的 skin 与当前相同不改宗，不同即申请改宗。class 非空仅 fantasy；目标为 fantasy 时可带 class，规则同 create；离开 fantasy 时置 null。door 来自实际入口壳，api 直连按 api、网页壳按 web；不把 door 当人机身份。model 按事实格式清洗，只作自报不验。
- 行动点：0（占位）；不发旧码、不创建会话。
- 前提：create 不需旧码；resume 需现存凭据，buried 在可恢复窗口内。初始化必需规则齐备才创建，不生成半个角色。
- 改宗前提（仅 skin 不同时，依次检查）：① tier≤3，否则 `NOT_ALLOWED {reason:"faith_locked"}`；② 当前地点 region 等于目标 skin 的出身区，否则 `NOT_HERE`；③ 不是本出身区非登记组织成员，否则 `NOT_ALLOWED {reason:"org"}`，须先 `use {op:"org_leave"}`。同 skin 不触发这三项改宗检查。
- 效果：create 原子写 identity 哈希、char draft、四个从 0 起的 skill learned、member bond、名声零行、初始化任务及预算；resume 按生命周期恢复 active 或保留 draft，更新所给字段和 seen_at；已 active 不再重复发初始资产。改宗同一事务更新 skin、origin_region 为目标，respawn_place 为目标出身区起点，结束旧登记组织 member、加入目标登记组织，写一条公开 deed（verb=enter）；不凭改宗传送当前 loc。死亡 life 不被 resume 洗掉。
- 返回：`char:本人行,identity_code:string|null,created:bool,changes:Change[]`；只有 create 的 identity_code 非空且只回一次，resume 固定 null；同时回 world 客户端参数。
- 拒绝：`IDENTITY_EXPIRED/NOT_HERE/NOT_ALLOWED`；其他非法参数用 INVALID_ARGUMENT。不因草码、来源、模型为空拒绝首入。

### 4.2 `look` —— 地点与事实查阅

- 参数可选：`section:place/people/items/tasks/deeds` 默认 place；`page:Page,limit:UInt|null`（默认与校验作用域见 §2）；无任意远处 place_id 参数。
- 行动点：0（占位）。
- 前提：draft/active；各页只读当前地点公开投影。
- 效果：不扣资源；首次看到地点更新 char.known_places，必要时写 discover/first_found；若有 find/reach 在办条件，当前同地点事实生成去重证据更新 task.progress。不能因同一 look 重复刷成长奖励。
- 返回：`place:公开地点行,section,rows:对应公开行[],page,has_more,snapshot_changed,counts:{people,items,tasks,deeds}`。section=place 返回地点与计数，rows 为空；其他分页读取，避免一次默认拉满地点所有历史。deeds 只取有权看到的当地点事迹。items 的 rows 仅为物实例、不附定义；用 def_id 查 §1.1 `GET /v1/defs`。
- 拒绝：`STATE_BLOCKED`。

### 4.3 `events` —— 三层增量

- 参数可选：`scope:self/place/world` 默认 self；`cursors:{self:Seq,place:{place_id:ID,after:Seq},world:Seq}`（缺省规则见事实格式）；`limit:UInt|null`，省略／null 默认 page_size。
- 行动点：0（占位）。
- 前提：有效持码角色；范围受 recipients/当前 loc 约束。
- 效果：不改游戏事实、不推进服务端已读，不改变别层游标。
- 返回：`scope,events:投影事件[],through:Seq,next_cursor:Seq,cursors:更新所选层后的游标对象,counts:{self:UInt,place:UInt,world:UInt},remaining:UInt,has_more:bool,place_reset:bool`；投影事件含 `other_speech/speech_status`。缺省 self 也必须附另外两层计数；计数是当前快照中各自 cursor 之后的可见行数，不是全服人数或总历史数。
- 拒绝：`INVALID_CURSOR/CURSOR_CONTEXT/CURSOR_EXPIRED`。
- S2 代理流程：保留返回的独立游标，先拉 self；看另外两层计数再决定是否拉，之后 look。这是世界卡给代理的流程，不是服务端禁止其他读取顺序；各 scope 可独立调用。当前 `/play` 网页刷新先 whoami、定义、look、任务与本人分页，之后按 place/self/world 拉事件，不先按 self 计数选择范围。所有入口均不能把 self 的 next_cursor 填给 place/world。

### 4.4 `whoami` —— 本人状态

- 参数可选：`section:char/items/skills/bonds/tasks/reputation/wanted` 默认 char；`page:Page,limit:UInt|null`（默认与校验作用域见 §2）。
- 行动点：0（占位）；不更改 life/state，仅更新鉴权访问时间。
- 返回：`char:本人行,derived:Stats,section,rows:对应本人行[],page,has_more,snapshot_changed,counts:各分区计数`；derived 不足规则时回 RULES_UNSET，不用皮补数。items 仅回本人物实例、skills 仅回本人已学行；均用 def_id 查 §1.1 `GET /v1/defs`，不在本回包附定义。
- 拒绝：仅共享集合。

### 4.5 `go` —— 走出口

- 参数：`dir:Direction`，词表／事实格式列明的十三方向之一。
- 行动点：1（占位）。
- 前提：本地点有该出口，未锁，守卫按中立条件放行，目的地存在。守卫只拦在本区有有效通缉的角色，回 `EXIT_BLOCKED {reason:"guard"}`。
- 效果：char.loc 改目的地、known_places 增加；写 travel，必要时 discover/first_found；更新在办 find/reach 证据；三层投影中本人 self、源／目的地 place 各发 moved。不自动完成或领奖。
- 返回：`from:ID,to:ID,changes:Change[]`；需完整新地事实再 look。
- 拒绝：`EXIT_BLOCKED`；无该出口用 NOT_FOUND。

### 4.6 `say` —— 同地言语或定向私信

- 参数：`text:string`（原文 Unicode 码点数须在 1..装载 text_max_chars，先校验长度再清洗；原文空串拒绝，清洗后空串仍成功且 available）；可选 `target:Ref<char>|null` 默认 null。null=当前地点发言；非空=定向，替代 tell，不要求同地。
- 行动点：1（占位）。
- 前提：定向对象为 draft/active 且不是已入土；npc 可接事实消息，但不靠 LLM 自动对话，不保证回应。
- 效果：按事实格式 §13 规范化控制／零宽字符，剥网址、整块及行内代码，发 speech 事件，临时内存投递清洗文字；不写散文、聊天历史、任务条件或关系同意。draft 可说、可收，不作为人口闸。
- 返回：`channel:place/direct,target:ID|null,other_speech:string,speech_status:available,delivered_event_ids:ID[]`，均为清洗后文本；正文按 speech_ttl_ticks 到期，也可能因容量淘汰或重启提前失效（事实格式 §13），不承诺持久离线信箱。
- 拒绝：`STATE_BLOCKED`（目标休眠／入土时 details 指目标状态但不暴露位置）；非法长度 INVALID_ARGUMENT。不得回传被剥除原文。

### 4.7 `take` —— 取地面物／采集

- 参数：`item:Ref<item>`，必须 instance。
- 行动点：1（占位）。
- 前提：available 且 holder 是当前 place；物无其他持有者；采集统一取已由规则生成的资源实例，不让客户端造数量。
- 效果：item.holder 改本人 char，equipped=false；写 take，更新 gather 进度证据。拾取不直接装备，因而不把背包当容量池；装备时才校验 cap。
- 返回：`item:实例公开行,changes:Change[]`。
- 拒绝：`NOT_HERE/ITEM_STATE`。

### 4.8 `give` —— 给物或币

- 参数：`target:Ref<char>`；`asset` 恰一个分支：`{kind:"item",item:Ref<item>}` 或 `{kind:"coin",amount:UInt}`，amount 必须正数（具体经济量占位）。
- 行动点：1（占位）。
- 前提：双方同地且 alive，目标 draft/active；物由本人持有、available、未装备、非孔内物；币余额够。不设置“人类才可接”的限制。
- 效果：item.holder 或双方 char.coin 原子改变；孔内物随其未装备容器整体转移，不复制；写 give。不是自动任务提交、不增加组织送物目标。
- 返回：`target:ID,changes:Change[]`，只给双方需要的物／余额变更，不公开对方完整余额给围观者。
- 拒绝：`NOT_HERE/NOT_ALLOWED/ITEM_STATE/INSUFFICIENT_RESOURCE`。

### 4.9 `use` —— 物、服务及社会关系的封闭交互

共同参数 `op` 必填，以下 16 个分支是 v1 的完整集合；每个操作都是明确前提与原子效果，不是自由文本万能动词。共同点数 1（占位），返回 `{op,changes:Change[],deed_id:ID,outcome:success}`；附加返回见表。共同前提为对象可见、所有涉及的本人物可用，服务 NPC 同地 alive。

| op 与其余必填参数 | 前提 | 事实效果／附加返回 | 额外拒绝 |
|---|---|---|---|
| `consume,item:ID` | 本人持有未装备 potion/scroll/map，effect 分别为 restore/learn/map（突破辅助分支不能 consume） | item.state 消耗；potion 改 char.vigor（不越上限），scroll 改 skill.level/cap（阶内规则），map 合并 known_places；写 use。 | ITEM_STATE、SKILL_CAP |
| `unlock,item:ID,dir:Direction` | 持有 key；本地出口 locked 且 key_def 匹配 | place.exits 对应项 locked=false；钥匙是否消耗按中立物规则，变化必须回 Change；写 use。 | ITEM_STATE、EXIT_BLOCKED |
| `equip,item:ID` | 本人 available 装备且耐久可用，装备及孔内 cap 合计不超 derived.cap_max | item.equipped=true；同一装备槽位的替换规则用 category，weapon/armor/accessory 各一个位置（数量占位，S5 规则给最终容量／槽位上限）；超过类别可用位置时拒绝，不暗卸别物；写 equip。 | ITEM_STATE、CAPACITY_EXCEEDED |
| `unequip,item:ID` | 本人已装备 | item.equipped=false；写 equip。 | ITEM_STATE |
| `socket,item:ID,core:ID,index:UInt` | 本人持有装备与 core，孔下标有效且空，若装备中则新容量仍够 | sockets[index]=core；core.holder 改 item；写 equip。 | ITEM_STATE、CAPACITY_EXCEEDED |
| `unsocket,item:ID,index:UInt` | 本人装备孔非空 | 核心 holder 改本人，孔置 null；任何费用／损耗按 S5 中立规则，规则未填不能默认免费；写 equip。 | ITEM_STATE、INSUFFICIENT_RESOURCE |
| `repair,item:ID,npc:ID` | 本人装备耐久不足；NPC archetype=repairer；币够 | char.coin 扣费、npc.coin 收费，item.dura 恢复；写 repair。 | ITEM_STATE、NOT_HERE、NOT_ALLOWED、INSUFFICIENT_RESOURCE |
| `buy,item:ID,npc:ID` | merchant 持有该实例、未装备可出售，买方币够 | 双方 coin 与 item.holder 原子交换；价格只取 S5 中立价；写 trade；返 `price:UInt`。 | ITEM_STATE、NOT_HERE、NOT_ALLOWED、INSUFFICIENT_RESOURCE |
| `sell,item:ID,npc:ID` | 本人未装备物、merchant 接收该类物且库存币够 | 双方 coin 与 item.holder 交换；写 trade；返 `price:UInt`。 | ITEM_STATE、NOT_HERE、NOT_ALLOWED、INSUFFICIENT_RESOURCE |
| `org_join,org:ID` | 在该组织 hall，不是已在该组织；若目标为登记组织，只准 world.registry_orgs[本人 origin_region]，否则 NOT_ALLOWED reason=registry；满足中立入会费用 | 结束原 member、新建 member 默认 rank，扣费用入 org.treasury；原组织离开代价同事务结算；写 org_leave/org_join。 | NOT_HERE、NOT_ALLOWED、INSUFFICIENT_RESOURCE |
| `org_leave` | 当前不是默认登记组织 | 结束 member，按 origin_region 回登记组织默认 member；扣中立叛离代价，改变组织声望；写 org_leave/org_join。 | NOT_ALLOWED、INSUFFICIENT_RESOURCE |
| `org_manage,action:promote/expel,target:ID` | 同组织，操作者 rank 对应权限 true；不能逐出登记组织成员；不能自行提升自己 | promote 升到 ranks 的下一个 rank，无下一级拒绝；expel 结束目标 member，目标回登记组织；写 org_promote 或 org_expel/org_join。 | NOT_ALLOWED、CONDITION_UNMET |
| `relation_offer,kind:mentor/ally,target:ID` | 双方同地，接收者 alive 且 draft/active（否则 NOT_ALLOWED reason=service）；mentor 发起者须满足下述教师前提；无相同 active bond | 仅写 relation_offer 事迹，result.proposal 保存 kind、a=发起者、b=接收者、expires_tick；不先建 active bond；向双方 self 发 relation_proposed；返 `offer:Ref<deed>`。 | NOT_HERE、NOT_ALLOWED、TEACHER_REQUIRED |

| `relation_end,bond:ID` | 本人为该 active mentor/ally 的端点 | bond.state=ended、ended_tick=当前刻；写 relation_end。 | NOT_ALLOWED |
| `enmity,target:ID,active:bool` | target 非本人，已有敌对状态与请求不同 | active=true 建立本人→target 的 enemy；false 结束该有向 bond；写 enmity，不强制对方反向结仇。 | NOT_ALLOWED、CONDITION_UNMET |

use 额外共享 `NOT_HERE/NOT_ALLOWED/INSUFFICIENT_RESOURCE/ITEM_STATE/CAPACITY_EXCEEDED/SKILL_CAP/EXIT_BLOCKED/TEACHER_REQUIRED/CONDITION_UNMET/OFFER_STATE` 仅在相应分支使用。NPC 各服务数值、价格、类别位置上限、师承提议期限均归 S5 balance_key；表中一个位置只是占位，不写进翻译表。买卖不另建支付系统；关系提议是结构化事迹，不是聊天同意；没有审核／审批流程。

### 4.10 `attack` —— 一次按刻对抗结算

- 参数：`target:Ref<char>`，不接 damage、胜负、随机种子或皮公式。
- 行动点：2（占位）。
- 前提：同地、对方 alive；双方可行动人口状态；place.combat 不是 safe，pve 只允许对 NPC；duel 只产生非致死胜负；pk 适用中立死亡规则。draft 与 active 同等，不额外禁攻击草码。
- 效果：同一中立 tier/stage/skill/装备/种子规则结算，改双方 vigor、装备 dura，发 combat_resolved；死亡写 life=dead/revive_tick、扣本阶 xp 不掉 tier、不一般掉物，pk 最多一件随身物掉至地点；不改身份 state。攻击 guard、pk 杀参与角色按规则记 wanted 并可生成备付系统悬赏；除害任务、首杀／首关按事实推进。必胜首战由 tutorial_opponent 原型中立规则实现。
- 返回：`outcome:win/lose/draw,winner:ID|null,changes:Change[],deed_id:ID,roll:Roll`；roll 是服务器产生，不是请求输入。对方私有字段只返回本次结算所需的中立输入和差量，不返回完整背包。
- 拒绝：`NOT_HERE/NOT_ALLOWED/INSUFFICIENT_RESOURCE`；目标已死亡 LIFE_BLOCKED。

### 4.11 `train` —— 按刻练功

- 参数：`mode:start/stop`；start 必填 `skill:SkillKey`，stop 不带 skill。
- 行动点：1（占位）。
- 前提：start 已学该技能、定义 tier 不高于本人且 level<cap；不预付也不要求当前潜能够升级。stop 已有 train_skill。设置不是立即凭请求次数刷收益。
- 效果：本事务修改 char.train_skill；按 S5 每 10 刻结一期，最多补结 144 期。新开／切换目标与 stop 将 last_yield_tick 设本刻，同目标重复 start 保留原起点，不靠切换多领。到期先生成 xp/potential，再按可用潜能和 cap 花潜能升技能；达到 cap／潜能不足只停止该期技能提升，不自动清除目标。stop 清目标。
- 返回：`train_skill:SkillKey|null,effective_tick:Tick`（本刻+1，表示下一刻按新设置处理，**不是保证下一刻首次发收益**）、`changes:Change[]`。新开／切换后须满一期才首次结收益；补期合并在一次 tick_yield 中，其 xp/potential 为生成量，不是扣升级消耗后的余额净增量，余额认 Change／whoami（事实格式 §11）。
- 拒绝：`SKILL_CAP/CONDITION_UNMET`（未学／定义阶不足或 stop 未在练功用 reason=training）。

### 4.12 `learn` —— 向高阶教师学

- 参数：`master:Ref<char>,skill:SkillKey,payment:bond/coin`。
- 行动点：1（占位）。
- 前提：同地，师 alive、tier 高于自己、该技能 level 高于自己；payment=bond 需有效 mentor（师为 a，己为 b）；payment=coin 按规则支付，玩家教师可凭已给出的关系／服务规则提供教学，不凭聊天授权。组织专属技能须已登记定义、成员资格满足其 org_id；不按皮禁学。
- 效果：学习者 skill.cap 提高，实际 level 增量按 S5；coin 分支双方 char.coin 转移；没有技能行先创建 level=0 后执行本次学习增量，严守 level≤cap；写 learn。
- 返回：`skill:学习者行,paid:Cost,changes:Change[]`。
- 拒绝：`NOT_HERE/TEACHER_REQUIRED/INSUFFICIENT_RESOURCE/NOT_ALLOWED`。

### 4.13 `task` —— 查、接、交、放弃

- 参数：`op:list/accept/submit/abandon`。list 可选 `filter:available/accepted` 默认 available，`page:Page,limit:UInt|null`（默认与校验作用域见 §2）；其余必填 `id:Ref<task>` 实例。
- 行动点：list 0，其他 1（均占位）。
- list 前提／效果：不耗点，available 返回本地 open 且 eligible_char 允许的任务；accepted 返回本人在办；只返回结构化 condition/reward，不回叙述。
- accept：任务 open 未到期、满足 eligible_char、在办数未达规则上限；本人的个人 system 未接任务在 list／accept 时移到当前地点（offer_place 随之更新），公开任务与悬赏仍须在 offer_place 接；设 taker=本人、state=accepted、accepted_seq=当前 deed_head、progress 清零，写 task_accept；不把接取前 slay/gather 证据拿来用。
- submit：本人 accepted、未到期、五模板条件由服务器核实；deliver/gather 在 condition 指定提交点，其他在 offer_place。原子执行交物／消耗、state=completed、发托管奖励、escrow 清空、改 char.coin/xp/potential、名声及奖励物 holder；系统日收益依 system_tasks_today 递减到零，仍可完成任务但不凭多请求刷未递减奖励。提交事务写 task_done／bounty_done，并发 task_changed、reward_granted 等本次结算事件；系统模板保持后续可接供给。**转正与组织周目标不在 submit 同事务生效**：下一刻 identity 阶段扫描已完成 system 任务使 draft→active，写 clock/identity 并向本人发 identity_state(reason=first_system_task)；组织阶段扫描已提交的 task_done 计进度，写 clock/org_goal，向目标名单 self 与 hall 的 place 发 org_changed，达标另发 reputation_changed。立即查询仍可能是 draft／旧目标，以下一刻事件或刷新事实为准。组织进度按提交事迹 tick 所属周及提交时成员关系归属，不按扫描时归属；周界先计旧周未入账提交、结算旧目标，再快照新周，已结算目标不重复计奖。
- abandon：本人 accepted；清 taker/证据返回 open（已到期则 expired 并退款）；不发奖励、不凭放弃重置 system_tasks_today。
- 返回：list 为 `{rows,page,has_more,snapshot_changed}`；修改为 `{task:实例行,reward:Reward|null,changes:Change[]}`。已完成重复 submit 为 TASK_STATE，不重复发奖。
- 拒绝：`TASK_STATE/TASK_LIMIT/CONDITION_UNMET/NOT_HERE/NOT_ALLOWED/INSUFFICIENT_RESOURCE`。

### 4.14 `bounty` —— 发悬赏／撤未接悬赏

- 参数：`op:post/cancel`。post 必填 `condition:Condition,reward:{coin:UInt,items:Ref<item>[]},expires_tick:Tick`；可选 `note:string|null` 默认 null。cancel 必填 `id:Ref<task>`。
- 行动点：1（占位）。
- post 前提：条件恰为五模板之一且引用可见有效，expires_tick 在未来并合中立期限范围，币和未装备可托管物足够，未结悬赏数未达占位上限；draft 可发，不另设转正闸。
- 效果：新 task instance，kind=bounty、tpl 从 condition 派生、issuer=本人、issuer_tier=当时 tier、offer_place=本地，扣 coin、物 holder=该 task，记录 escrow；系统按 issuer_tier 计算可得 rep，xp/potential=0；发 task_changed，写 bounty_post。note 如有仅走 other_speech 临时投递，不存任务正文。
- cancel 前提：发单者本人、state=open 未承接；效果 cancelled、escrow 原额退回并清零，写 task_release；accepted 拒绝撤单。
- 返回：`task:实例行,changes:Change[],other_speech:string|null`（仅清洗后附言即时返回，非事实字段）。
- 拒绝：`TASK_LIMIT/TASK_STATE/INSUFFICIENT_RESOURCE/ITEM_STATE/NOT_ALLOWED/CONDITION_UNMET`。

### 4.15 `build` —— 只提交数据定义

- 参数：`kind:place/item/task`、`data:该类建造字段对象`；可选 `note:string|null` 默认 null；place 还必填 `attach:{from:Ref<place>,dir:Direction,back:Direction}`。item/task 禁止 attach。
- 行动点：1（占位）。
- 前提：tier 达装载 build_min_tier（3 为占位），格式／引用／数值阶内／内容键唯一；不含散文、脚本、公式、身份或服务器字段；地点扩展从本人当前地点 build_anchor 的空闲出口起，owner_org 非空时需其成员，机器自动校验不另审批。
- data 字段白名单：place 为 `content_key,region,kind,features,tier,danger,combat,owner_org`，exits 由 attach 原子生成双向边；item 为 definition 的 `content_key,kind,tier,grade,element,slots,cap,dura_max,modifiers,effect`；task 为 template 的 `content_key,tpl,tier,stage,condition,reward_spec,duration_ticks`。place／item definition／task template 的 tier 均不得越过建造者当前 tier，数值仍需 S5 该阶边界，不让客户端把 grade 当无限加成。content_key 须为本 realm、对应 kind 的 `content.<realm>.<type>.<local>`，公开建造 type 仅 place/item/task，local 为 1..64 位小写 ASCII 字母、数字或下划线。装备 modifiers 与 core 的 effect.modifiers 各分量非负，装备 dura_max≥1，且均遵守阶／品级上界。task template 的 deliver.to_char（非空时）、find.target、slay.target（非空时）只准 npc/official，不准 player，非法引用回 BUILD_INVALID reason=reference；这是模板边界，不套给玩家 bounty 的角色引用，细节见事实格式 §9.1。
- 效果：服务器分 ID/by/时间，写新 place 或 item definition 或 task template；地点同时修改旧 place.exits；item 不凭建造直接生成玩家资产；task 不凭模板立即发奖，由规则生成实例；写 build 并发 built。附言经统一清洗后只在本次 result.other_speech 回显给调用者，不生成 speech、不存 SpeechStore、不向其他角色投递；built 事件也不带附言。
- 返回：`table:place/item/task,id:ID,record:公开行,changes:Change[],other_speech:string|null`。
- 拒绝：`BUILD_INVALID/DUPLICATE_KEY/INVALID_KEY/NOT_ALLOWED/NOT_HERE/CONDITION_UNMET`。

### 4.16 `breakthrough` —— 小段、升阶、轮回同一原语

- 参数：`mode:stage/tier/cycle`；可选 `item:Ref<item>|null` 默认 null（只允许 effect.kind=breakthrough 的 potion 定义；bonus 为中立占位，S5 定终值，未登记不猜效果）。
- 行动点：2（占位）。
- 前提：xp 达当前阈值，所需练功／技能条件满足；stage 仅 stage<4；tier 仅 stage=4 且 tier<9；cycle 仅 tier=9 且 stage=4。item 如有本人未装备、可消耗且用途匹配。
- 效果：stage 成功 stage+1，按 S5 扣 xp；tier 按服务器种子检定，成功 tier+1/stage=1，失败扣部分 xp 不致死；cycle 回 tier=1/stage=1、cycles+1，保留名声与规定 legacy，技能／成长重置数值由 S5 同一公式定。装备超新 cap 时原子卸装至可用（按 item.id 降序卸装，保留物，不能悄悄删除）；不引入十阶以上体系。耗物、损失及检定全部反映 Changes/Roll。
- 返回：`mode,outcome:success/failure,tier:Tier,stage:Stage,cycles:UInt,changes:Change[],roll:Roll|null`；业务失败仍 ok=true 并扣本次点数。
- 拒绝：`CONDITION_UNMET/INSUFFICIENT_RESOURCE/ITEM_STATE/CAPACITY_EXCEEDED`（仅无法保持事实一致时，不以皮类别为理由）。

## 5. 引擎触发而非额外动词

时钟处理身份清理、死亡复活、定量练功、NPC 巡逻／资源补充／再生、任务到期退款、通缉到期、组织周目标。需要记录的刻事迹使用 deed.verb=`clock`，不能调用 `/v1/actions/clock`；不承诺每次维护都有事迹／增量。资源点补充与商人补货当前只插入物实例、更新私有到期记录，不写 deed/event，不能靠 events 得知补货；地面物须重新 look(items)，商人库存须刷新相应库存读面。公开页、翻译装载、开服事实导入不是玩家新动词；不把治理接口、找回、跨服、MCP 或行动链接塞进 v1。

首关与模板、地图买卖、装备孔位、组织入升叛逐、师承／仇盟均已有明确参数与表字段落点；不让 S9 从自然语言猜行为。所有规则版本均为中立，不能查 skin/class 决定费用、战力、成功率或奖励。S2 可先教简单循环 `enter → events → look → task accept → go/attack/take → task submit`，其他分支按需展示，不要求首回合塞满所有表。
