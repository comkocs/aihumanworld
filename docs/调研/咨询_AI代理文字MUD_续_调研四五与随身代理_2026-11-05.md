## 调研四:免费聊天窗能否当玩家(Explore·Haiku)

说明:只用了搜索与 1 次抓取(官方页被拦截,未取得)。多数结论来自二手博客,已标注。

**1. 免费档能力**
结论:只有 Gemini API 的 URL context 能确认免费;其余产品的"贴网址读取"支持程度不一,"每回合开新网址"和"免费 POST / 外部工具"基本未证实。
- Gemini API 定价页列出 URL context 免费层免费 https://ai.google.dev/gemini-api/docs/pricing ;"每请求 20 个 URL"仅见第三方(未核实)。Gemini 网页/App 的贴链接行为未核实。
- ChatGPT 免费档:网页搜索免费(二手);云端 Browser 不含 Free 档 https://learn.chatgpt.com/docs/browser ;贴链接读取未核实。
- Kimi:官方说明搜索支持指定 URL 访问 https://www.kimi.com/en/help/features/search ;外网与敏感话题效果差(2024 旧文)。
- DeepSeek:联网搜索免费(二手)https://aieii.com/posts/2026-08-19-kimi-doubao-deepseek-free-quota-pricing/ ;贴 URL 读取未核实。
- 豆包:未找到官方说明,贴链接与免费次数均未核实。
- Claude.ai 免费:可加 1 个远程 MCP connector https://claude.com/docs/connectors/custom/remote-mcp ;免费档 web fetch 仅一篇二手称有(未核实)。
- 通义、文心、元宝、Gemini App:未查到可靠来源。

**2. 用户自建智能体**
结论:Gemini Gems 免费可建可分享;GPTs 免费不能建;扣子免费可建,但发布到豆包渠道疑似仅国内版。
- Gemini Gems:免费可建,指令框即长期指令,可生成分享链接,接收方需有访问权 https://support.google.com/gemini/answer/16504957 。带文件说明、外部接口未核实。
- ChatGPT GPTs:免费只能用 GPT Store,不能创建 https://en.wikipedia.org/wiki/GPT_Store (无日期)。
- 豆包/扣子:扣子免费版可用工作流、知识库、多智能体(二手,2026-05)https://www.aitoollab.cn/articles/coze-2-0-complete-tutorial-guide/ ;豆包发布渠道仅国内版(二手,出处待核)。
- Kimi、通义智能体、Claude Projects:未查到。

**3. 把网址当动作**
结论:没有找到公开的"聊天 AI 通过 GET 链接操作文字游戏"案例。
- 最近似:llmskirmish 允许命令行向 LLM 对战网页提交策略,无需登录 https://news.ycombinator.com/item?id=47149586 ;KanGame PR #20 用工具调用映射动作并提供 GET 动作端点 https://github.com/TopTuK/KanGame/pull/20
- 已记录的坑:GET 带副作用会被预取提前触发 https://linkutm.com/glossary/link-prefetching ;链接预览可零点击外泄数据 https://www.theregister.com/security/2026/02/10/ai-agents-can-spill-secrets-via-malicious-link-previews/4606257
- 缓存、拦截、重复请求、安全过滤的实测记录:未查到(未核实)。

**4. AI 可读网站先例**
结论:llms.txt 已存在但采用率低、不是正式标准;"每页一个房间、每个链接一个动作"的超文本游戏未找到先例。
- llms.txt 是社区约定,采用率统计口径差异大(来源多为营销博客)。https://www.interodigital.com/blog/what-is-llms-txt/
- 超媒体给 agent 用的讨论:有 2026 年论文 https://arxiv.org/pdf/2606.19116 (仅看摘要,未读全文)。
- 近似先例:房间图式文字冒险 https://arxiv.org/pdf/2505.03547 ;LLM 驱动文字冒险 https://ianbicking.org/blog/2025/07/intra-llm-text-adventure

**5. 技能与插件渠道**
结论:Claude Code 与 Gemini CLI 都能一条命令装;ClawHub 与 MCP 目录规模大但数字互相矛盾,且有安全与服务变动问题。
- Claude Code:`/plugin marketplace add <owner/repo>` 后 `/plugin install`,可用 `#tag` 固定版本 https://code.claude.com/docs/en/plugins/install ;恶意 marketplace 风险 https://promptarmor.substack.com/p/hijacking-claude-code-via-injected
- Gemini CLI:`gemini extensions install <git 地址或路径>`,支持 `--ref` https://geminicli.com/docs/cli/cli-reference/
- ClawHub:约 13,729 个技能(2026-03,二手);`clawhub install <slug>`;恶意技能报告从 341 到 820+ 不等 https://openclawdc.com/blog/openclaw-clawhub-guide/
- MCP:Smithery 据称 2026-10-31 关闭代理(二手);目录数 2.6 万至 2.7 万(二手);官方 Registry 数字差异大 https://callsphere.ai/blog/vw4g-mcp-registry-catalogs-smithery-mcp-so-comparison-2026
- Codex 插件:未查到。

**对"让用豆包 / Gemini 免费窗的人也能玩同一个文字世界"的进入方式排序**
1. 人工中转加纯文本世界卡(最现实,零服务依赖):世界状态写成纯文本或 Markdown,玩家贴进任意免费窗,AI 输出命令,玩家手动提交到游戏网页再贴回结果。硬限制:AI 不能自主动作,每回合需人工搬运,长对话易遗忘。
2. Gemini Gem 分享链接:免费可建可分享,玩家一键打开。硬限制:Gem 自主联网与调用接口未核实,世界状态仍需贴入;需 Google 账号。
3. 扣子/豆包智能体接自建 HTTP 插件:最接近"一键且 AI 直接调接口"。硬限制:豆包渠道仅国内版(二手),免费调用额度未核实,需自建服务。
4. Claude.ai 免费 1 个远程 MCP connector:可真正调用动作。硬限制:仅 1 个,需 HTTPS 远程 MCP 服务,免费档 web fetch 未核实。
5. 贴 URL 读状态(Kimi、DeepSeek、豆包等):只能读,每回合人工贴链接。硬限制:免费档每轮抓取与缓存未核实,不能 POST。
无论选哪条,都应让"URL 动作"只是可选加速,世界规则和状态本身用纯文本可读的命令表达。

## 调研五:文件即游戏与联邦化世界先例(Explore·Haiku)

说明:来源多为媒体、博客与聚合站,数据多为自述或快照,逐条标注了未核实项。

### 1. 提示词即游戏
结论:这类作品靠可复制文本与二创传播,单次爆发快,但多人持久状态的先例很少。
- 人生重开模拟器原版在百度贴吧发布 3 天约 2 亿次游玩,第 8 天约 10 亿(据维基百科)。https://zh.wikipedia.org/zh-cn/%E4%BA%BA%E7%94%9F%E9%87%8D%E5%BC%80%E6%A8%A1%E6%8B%9F%E5%99%A8
- AI 版多为一段提示词粘贴即玩,内容实时生成,状态一般只存在于对话上下文中(机制未核实)。2026 年 10 月《80亿分之1》借 Claude 约 4 小时做出,两天访问量近前一日 7 倍,数据为作者自述。https://www.huxiu.com/article/4899936.html
- SillyTavern:角色卡为 PNG 或 JSON(V2/V3 规范),lorebook 可内嵌在卡内,按关键词触发注入。GitHub 星标约 3.5 万,但星标不等于用户数,未找到活跃用户数。https://github.com/SillyTavern/SillyTavern 、https://arcanumrpgs.com/blog/sillytavern-character-cards/
- Chub.ai 角色数各家说法从 6 万到 200 万不等,未核实。https://ai.miraheze.org/wiki/Chub_AI
- AI Dungeon:2019 年以 GPT-2 起步;2025 年 6 月因高峰宕机道歉并转向自建基础设施;Steam 版已退役;2026 年 4 月推出 Voyage 平台。多人模式为各玩家各控一个角色轮流行动(二手描述,未核实)。https://techcrunch.com/2026/04/21/voyage-is-an-ai-rpg-platform-for-creating-custom-gaming-worlds-with-ai-generated-npc-interactions/ 、https://steamdb.info/app/1519310/charts/
- 豆包智能体功能 2026 年 7 月 15 日下线,原因说法不一(产品调整或拟人智能体新规)。https://www.nbd.com.cn/articles/2026-07-04/4452157.html 未找到豆包、Gemini、ChatGPT 上「文字游戏」流行的可靠数据。GPT Store 2024 年 1 月上线,adventure 类 GPT 无人数数据。

### 2. MUD 互联
结论:I3 和 IMC2 做到了跨 MUD 聊天、查人与列表,没有见到跨 MUD 角色移动的规范或实装。
- I3 核心服务为 tell、emoteto、who、locate、finger,mudlist 由路由提供。https://mudstandards.org/intermud/intermud3/ 、https://wl.mud.de/mud/doc/misc/intermud3.html
- IMC2 以 channels 为主,附带 emote 与 finger;who、tell 两者都支持。https://muds.fandom.com/wiki/InterMUD 、https://mudstandards.org/intermud/intermud2/
- Dead Souls 文档称跨站 tell 经路由明文传输,不保证私密。http://dead-souls.net/ds-admin-faq.html
- 现存实现有 LuminariMUD 的 I3 客户端。https://github.com/LuminariMUD/Intermud3
- 1990 年代的讨论中有「角色存入源站、在目的站新建并链接」的单向转移构想,未见实装。https://groups.google.com/g/rec.games.mud.lp/c/u6xEC7WWJUY
- 「多台服务器组成一个大世界」只找到学生项目(集群拆分单个 MUD 组件),未找到面向玩家的公开运营案例,未核实。

### 3. 联邦化(ActivityPub / Matrix)
结论:两者在游戏中都停留在小型实验与概念层,未找到运营中的联邦游戏世界。
- FediGames 是 ActivityPub 上的小游戏框架,测试于 Mastodon 与 Firefish,资料已约两年,可能停滞。https://socialhub.activitypub.rocks/t/fedigames/4146
- Kevin Hoffman 的博客提出用 ActivityPub 互发游戏 activity 的设想,作者称尚未实现。https://kevinhoffman.blog/post/fediverse_gaming/
- Element 用 MatrixRTC 做了两个多人游戏 demo,共享槽位放在 state events,短期数据用 sticky events。https://element.io/blog/exploring-matrixrtc-real-time-communication-in-rooms/
- Matrix-CRDT 实验把实时共享状态存入 room,属原型。https://news.ycombinator.com/item?id=29978659
- 社区反映大房间加入慢,因为需要同步全部 room state。未找到 Matrix 游戏同步的公开基准。

### 4. 链上 / 自治世界
结论:愿景远大于实际规模,Lattice 已于 2026 年收缩并关停 Redstone,是最明确的负面教训。
- MUD 是 Lattice 的 EVM 链上 ECS 框架,MIT 开源。https://lattice.xyz/
- OPCraft 于 2022 年基于 OP Stack 上线,计划 2022 年 10 月 31 日冻结,此后现状未核实。https://optimism.io/blog/announcing-opcraft-an-autonomous-world-built-on-the-op-stack
- Sky Strife 每个操作约 2 秒内上链,体验介于实时与回合制之间;三季后转为自治模式。DappRadar 标注 2025 年 4 月停运,与官方说法冲突,未核实。https://lattice.xyz/blog/sky-strife-autonomous-mode
- Dark Forest 的 v0.6 各轮约 1700 人参与,九天内白名单玩家约 1900 人,共耗约 1.7 万亿 gas 单位。团队称暂停轮次开发,未宣告关停。https://blog.zkga.me/v6-r1-wrapup 、https://blog.zkga.me/v6-r3-wrapup
- Lattice 2026 年 4 月宣布结束运营,Redstone 于 2026 年 5 月 15 日 23:59 UTC 关停,称从未形成可持续业务;MUD、Quarry、Dozer 已开源。合约内资产不可经 L1 提取,需提前取回。https://x.com/latticexyz/status/2044103611072835744
- 费用与延迟:BITKRAFT 指出链上游戏普遍存在高费用、高延迟与邻居噪声问题。https://www.bitkraft.vc/insights/fully-onchain-games-thesis/

### 5. P2P / CRDT 无中心同步
结论:未找到基于 Yjs 或 Automerge 的公开多人游戏世界实践,作弊与仲裁仍以权威服务器为主流做法。
- 搜索未命中 Yjs 或 Automerge 的游戏案例。
- 通行做法是服务端权威:重算关键逻辑、过滤非法输入。https://accelbyte.io/blog/server-authoritative-logic-to-prevent-cheating 、https://dev.to/aplusgamesstudio/anti-cheat-for-small-multiplayer-games-what-works-4a6g
- CRDT 保证收敛,不负责仲裁。无中心时无处拒绝非法操作,这是通识判断,未核实。

### 6. 文字世界的存储量级
结论:未找到任何 MUD 世界数据或日志规模的公开数据,老 MUD 的日志与玩家档处理方式也无可靠来源。
- AberMUD 代码库约 224 KB,仅指代码。https://en.wikipedia.org/wiki/AberMUD
- AVATAR MUD 于 1994 年 8 月数据丢失后转向 Merc 代码库。https://en.wikipedia.org/wiki/AVATAR_MUD
- Minecraft 服务器经验值:玩家数据约 1 至 100 MB,日志与配置约 10 至 500 MB。这是类比,非 MUD 数据。https://wisehosting.com/blog/how-much-storage-for-a-minecraft-server

### 如果目标是「轻量、谁都能进、人类与 AI 同玩的共享文字世界」,这些先例给出的三条最硬的结论
1. 共享状态必须有一个权威写入者。 MUD 单服、链上 EVM、AI 文字游戏中的「规则引擎持有状态、LLM 只负责叙述」,成功的案例都把「谁说了算」放在一处。CRDT 与联邦设想在公开资料中都未解决仲裁与作弊。
2. 跨服互通止于聊天与查人,角色跨服移动没有成熟规范。 I3 与 IMC2 历经二十多年仍停在 tell、who、finger。要做「一个大世界」,必须自行定义角色归属与状态迁移。
3. 失败多源于运营与成本,而非协议。 Lattice 关停、Dark Forest 暂停、Sky Strife 转自治,都与费用、延迟与可持续性有关。「文件即游戏」多为单人、一次性传播,多人持久运行的先例很少。
