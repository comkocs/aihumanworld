## 0. 读法与口径

- 同阶同强:表里没有皮、职业、入口、模型任何字段;形态标签(body)全 100%,NPC 原型中教学对手与怪物另有系数,其余全 100%。皮只换名字,数只在这里。
- 弱约束:没有任何限速、验证、反作弊数值。每日递减、阶衰减、周目标均摊都只是递减,不拦人;读取不耗点,不加请求上限。
- 不做清单照产品文档第十一节;没有实时战斗、没有拍卖行、没有第二种货币。
- 做法:先定「几天过一格」的节奏,倒推 xp 需求;战力阶梯另定比例(阶间 ≥1.778 倍);其余数全由这两条和下面参数派生。表是真值,公式只说明怎么算出来的。
- 标「荐」= 我在几种合理取法里选的取向值,S10 / 总编排可调,调了换 `balance.v2`;不标 = 产品文档或协议直接推出、或纯标度。

- 日与周:`day_index = 刻号 ÷ 1440`、`week_index = 刻号 ÷ 10080`,取世界时钟,不取在线时长。

- 体力回复:在每刻预算刷新时,按 `ap_tick` 到当前刻的差刻,补 `差刻 × vigor_max × 200 ÷ 10000`(至少补 1),不超过 vigor_max;不新增字段。

### 3.4 属性派生(角色 / NPC 同一公式)

```
base      = grid[阶][段]
power     = floor(base.power  × (10000 + 27×lv_strike + legacy_bp) / 10000) + Σ 已装备且耐久>0 的 power 修正(含孔内核心)
guard     = floor(base.guard  × (10000 + 27×lv_guard  + legacy_bp) / 10000) + Σ guard 修正
speed     = floor(base.speed  × (10000 + 27×lv_move   + legacy_bp) / 10000) + Σ speed 修正
vigor_max = floor(base.vigor_max × (10000 + 27×lv_inner + legacy_bp) / 10000) + Σ vigor 修正
cap_max   = tiers[阶].cap_max(与小段、技能、轮回无关)
lv_*      = 同一 base 下所有技能(含组织专属)的最高 level;legacy_bp = min(legacy, 1000) × 1
NPC       = 基础格值 × combat.npc_rating_bp / 10000,无装备、无技能
```
为什么:战力分三项等权相加,所以武器 / 护具 / 饰件、攻 / 守 / 身法三类技能的价值相等,任何搭配同价;inner 不进战力分,只管体力和升阶门槛(第 4 节),保持「内息」不另生一套资源。

### 3.5 九阶无倒挂的算账

同阶最强配置 = 第四小段(×1.15)× (1 + 技能满级加成 + 轮回满加成 10%) + 装备与核心在容量池内的最大加成(按每点 cap 的最高预算效率估)。对每一阶的该上限除以下一阶第一格(`unit`),最大比值为 **0.923**(<1):下一阶赤手一段的分数也高于上一阶全副武装的四段。越阶穿高阶装备受 cap_max 限制(阶间 cap 比低于战力比),按同一方式估算仍低于下一阶赤手一段。倒挂检查作用于战力数(属性、修正预算);容量、价格、耐久实际也按 (阶, 品级) 逐项递增;孔位数按品级定、不随阶。

## 5. 突破检定与轮回

小段、升阶、轮回走同一原语:`成功率 p = clamp(基础 + 道具加成 − 阶衰减, 下限, 上限)`;小段的参数使 p 恒为 10000、不抽签(roll = null)。

```
前提   xp ≥ 本格 xp_need,inner 等级 ≥ 本格 inner_req;stage 仅 stage<4,tier 仅 stage=4 且 tier<9,cycle 仅 tier=9 且 stage=4
p      = clamp(9500 + bonus_bp − 700×(阶−1), 1000, 9500);bonus_bp 取突破药的品级加成(无药为 0)
抽样   value = u32(seed, 'bt') % 10000;value < p 成功;Roll.value = value
成功   xp −= xp_need;stage+1(或 tier+1、stage=1)
失败   xp −= xp_need × 20%(至多扣到 0);不掉阶、不掉物、不致死;药照耗;ok=true、outcome=failure
轮回   cycle 成功:tier=1、stage=1、xp=0、potential=0、cycles+1、legacy = min(legacy+100, 1000)、技能 level 与 cap 各取一半再受一阶上限截断;币、物、名声、关系保留,vigor 回满;装备超新 cap 时按 item.id 降序卸装
```
为什么:失败的代价是进度(20% 的格需求),不是性命,也不是装备;成功率随阶下降,所以高阶更依赖药;药只在阶相等时可用,避免高阶药通吃。

## 6. 对抗结算

```
R      = power + guard + speed(派生后);R_eff = R × (7000×vigor_max + 3000×vigor) / (10000 × vigor_max)
seed   = rules_revision:realm:tick:deed_seq:actor:target(无目标写 -)
j_X    = u32(seed, 'A' 或 'D') % 3001 − 1500           攻方抽 A,守方抽 D
s_X    = R_eff_X × (10000 + j_X);Roll.value = s_攻 × 10000 ÷ s_守
hi,lo  = 两者较大 / 较小;gap = (hi − lo) × 10000 ÷ hi;gap < 200 → 平局,否则 hi 者胜
输家   vigor −= vigor_max × min(10000, 2500 + gap) ÷ 10000
赢家   vigor −= vigor_max × 500 ÷ 10000;平局双方各 −1000 bp
磨损   每件已装备物:输家 −4%、赢家 −1%、平局 −2% 的 dura_max(至少 1,至多扣到 0)
死亡   pk / pve 中 vigor ≤ 0 → life=dead、revive_tick = 当刻 + 10、xp −= min(xp, 本格 xp_need × 10%);复活时 vigor = vigor_max × 50%
duel   vigor 至少剩 1,不死、不扣 xp、不掉物
教学   教学对手各项属性 = 一阶一段格值 × 30%,输一次即倒(vigor 归零),下一刻再生;玩家必胜且只吃赢家 5% 反震
掉落   pk 地死亡:若 u32(seed, 'dropchance') % 10000 < 5000,则从未装备的随身物中取下标 u32(seed, 'drop') % 件数 的一件放到地点
怪物   参与角色在非 duel 地点击杀 archetype=monster 的 NPC:若 u32(seed, 'mondrop') % 10000 < 2000,在地点新生成一件该怪本阶的装备实例。品级按权重 7000/2500/500(一/二/三品)用 u32(seed, 'mongrade') 抽,种类在库内该阶该品实际有货的装备种类里用 u32(seed, 'monkind') 均匀抽,同一种类多条定义再用 u32(seed, 'mondef') 按 id 序抽一条;打玩家不走这条,safe 地点仍禁止攻击 NPC
```

## 7. 容量池与装备

`equipment.table` 的行适用于武器 / 护具 / 饰件三类:同阶同品级数字相同,默认把 `budget` 放进各类主属性(见下 `equipment.main_stat`);S16 可把预算在 power / guard / speed 之间分配(vigor 按 2:1 折算),总和不得超过 `budget`。`cap` 为占用容量(大于等于本表才合法,越低越占便宜,故建造下限),`dura_max`、`slots`、`price` 同表。

`cap_max` 见第 3.1 节;装备容量 = 已装备件 cap 与孔内核心 cap 合计 ≤ cap_max。三类位置 4 件(1+1+2)。

```
budget(阶,品级) = unit × mod_share_bp ÷ 10000;     cap = 四舍五入(cap_max × cap_share_bp ÷ 10000)
dura_max = 100 + 10 × (3×(阶−1) + 品级−1);         price = unit × price_bp ÷ 10000,一阶一品例外为 190
核心同理:budget = unit × mod_share_bp ÷ 10000;cap、price 按核心品级系数及原公式,不套装备价格例外
建造边界(S12):modifiers 预算 ≤ 本表 budget;cap ≥ 本表 cap;dura_max ≤ 本表;slots ≤ 本表;definition.tier ≤ 建造者当前阶
```
为什么:预算占 unit 的 4% / 5% / 6%(四件传说合计 24%),cap 占 cap_max 的 16.5% / 19% / 22%(四件传说 88%,余下 12% 放核心),修正与 cap 都逐品级、逐阶严格递增且无倒挂(上一阶传说低于下一阶普通)。

## 8. 经济

币只有一种;来源 = 系统任务(满额每天 3.0 件)与悬赏转手;去向 = 买装备、修理、学艺、地图、入会与叛离、拆核心。NPC 收的币每天重置到币池,多收部分即回收。

```
系统任务奖励   = floor(tiers[阶].{task_coin,task_xp,task_potential} × tpl_bp ÷ 10000) × max(0, 10000 − 2000×n) ÷ 10000;n = 当日已交系统奖励件数
                  通缉悬赏等系统出资的单也计 n;玩家悬赏的币与物不受此递减,按承诺原额支付
悬赏声望       = tiers[发单人发单时的阶].rep_bounty(与币额无关,不随事后升阶重算)
修理           = ceil(price × 20% × 缺口 ÷ dura_max)
买 / 卖        = 标价 ×100% / ×40%
组织周目标     = 名单人数 × 每人量(系统任务 5 / 送物 8,至少 3),达标名单内每人 +5 点组织声望
个人首次到达按 min(角色阶, 地点阶),首杀 / 首通按目标所在阶,各取对应 task_xp、task_potential 乘 54% / 15% / 5%,另加对应 rep_bounty × 1 / 2 / 3;出生地已到过,世界首探事迹不另加奖
```
为什么:每日递减保证系统给的是固定上限、人人一样;玩家悬赏是玩家自己的钱,不被系统吞;声望只按发单人阶折算,不可能靠大额造声望;组织目标按人头均摊,大组织不因人多而更容易。

## 9. 期限与人口清理(90 天冲突的落点)

|---|---|---|
| 同阶发起击杀(五阶对五阶) | PK 奖 3000 修为(2 件) | 红名 240 刻,挂悬赏 9000 修为 + 1000 币 |

`combat.monster_kill_xp_bp` 由 234 改为 825,其余一概不动。一次 `attack` 对 `archetype: monster` 的 NPC(以及怪物发起的伏击)把整场一次结算完:同一套确定性单回合规则连打,直到一方体力为 0,或打满 8 回合仍未分出,就判平——双方留着最后一回合后的体力,都受伤、怪不死。同回合双方都到 0 算参与角色胜。胜了怪死,掉落、首杀、`reward` 都在这一下的回包里;负了照旧扣体力,体力到 0 即阵亡、掉修为。不加准入门槛,打不打由 AI 看怪的阶段自己判断。参与角色之间的切磋与 PK、怪物 30 刻再生、掉落概率、伏击频率都不变,打怪的行动点仍是 2。`meta.revision_key` 与 `world_rules.balance_key` 同步由 `balance.v1.12` 升为 `balance.v1.13`。

取数理由:一阶一段裸装对 9000 折算的同阶怪,整场约 3.24 回合见分晓(2 万个种子里 8 回合上限截断 0 次),胜约 91.6%、负约 8.3%、平约 0.1%。一次攻击 2 点行动点,怪物 30 刻再生。静态内容每个地点每阶只有 1 只常驻怪,所以瓶颈是再生:一天 1440 刻,`1440 ÷ 30 = 48` 只。每只给 `floor(满额任务修为 × 825 / 10000)`,一阶 `floor(300 × 825 / 10000) = 24`,一天 `48 × 24 = 1152`,贴满勤练级 1188(低 3.0%)。二至九阶一天 1776 / 2688 / 3936 / 5904 / 9072 / 13440 / 20160 / 30480,与各阶满勤练级的差都在 3.1% 以内。聊天 > 探索 > 切磋 > 练级 ≈ 打本阶怪 ≈ PK 仍成立。行动点不改:一天 4320 点行动点打 48 只只用 96 点,改它不改变能打几只。详见 `docs/数值/一天收益总账_2026-11-07.md`。
