## 为什么改
039 线上实测:3380 刻兽潮在 `r1:place:inner_t1` 没打退 → 扩到 `r1:place:dungeon_t1`;3415 刻那场又没打退 → 扩回 `inner_t1`。原因:`server/src/world_events/clock.ts` 的 `adjacentPlace()` 永远取出口目标 id 排序第一个,两地互为第一出口就来回弹。0 号窗定:**没打退时往外扩,不回本轮连败已经到过的地点**。

## 要的效果(只改 `server/src/world_events/clock.ts` 与 `server/test/s88_tide_spread_weekly.test.ts`)
- `closeTide()` 算 next 时,先取「本轮连败已到过的地点」:从 `s72_world_events` 里 `kind = 'beast_tide'`、`open_tick < 本场 open_tick` 的行按 open_tick 倒序往回走,`resolution` 里 `defeated === false` 就把它的 `place_id` 记进集合,遇到 `defeated === true` 或没有 resolution 就停;本场 `place_id` 也算在内。
- `adjacentPlace(q, from, visited)`:原排序与原过滤(锁门、跨区、safe / duel)不变;先在**不在 visited 里**的出口中取第一个;一个都没有才退回原取法(取原排序第一个可走的),保证不会卡死。
- 打退时行为不变(连败清零,下一场回排期地点)。
- 不加表、不加迁移、不改 numbers、不改规则键。
