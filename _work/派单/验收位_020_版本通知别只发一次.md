# 验收位派单 020 · 入口更新后 AI 自己知道去重读(版本通知别只发一次)

派单方:AI 人间·需求与验收位;时刻 2026-11-08 01:08。一句话:**每次入口更新,设计者都得手动对 Grok 说「使用最新版的md来进行游戏，更新了」它才重读。原因:版本通知每个角色每个版本只在更新后第一次操作的回包里出现一次,Grok 一次连发多条命令很容易漏看,漏了就再也不出现。让 AI 任何时候都能看出「入口有新版」。**

## 需求出处
- 设计者 11-08 00:36~01:08 本位窗:「每次更新我好像都需要打一个这样的内容，他才会进行更新」(附截图:设计者打「使用最新版的md来进行游戏，更新了」;本位原话件 11-08 第 3 条)。

## 现象(本位读码)
- `server/src/verbs/envelope_extras.ts` noticeFor:新 rev 发布后,角色下一次成功请求的回包带一次 `notice`,同进程 memo 记下后不再出现。
- 设计者 Grok 截图(11-08 00:06~00:09):Grok 会把 events / events world / look / task 四条 curl 用 && 连成一条发;回包混在一起,一次性的 notice 容易被略过。
- start.md 第 3 行:「If an action reply carries a `notice` with a newer revision, re-read this file once」——只认 notice,没有别的信号。

## 要的效果(做法归做的人)
1. 每个带身份码的成功回包都带一个很小的当前入口版本号字段(例 `guide_rev`),AI 任何一次回包都能和自己读过的 Guide revision 对比。
2. 完整 notice 别只发一次:发布后对每个角色多发几次(次数或刻数你定),或直到它的回包里出现过若干次;notice.text 照旧写「新:…」要点,AI 不重读也知道大意。
3. 三份入口第 3 行同步改:「每个回包都带 guide_rev;它比你读过的 revision 新,就重读本文件一次」。
4. 不加强制(不因没重读而拒绝动作),不改别的协议字段。

## 验收(本位)
老角色在新 rev 发布后连续几次请求,回包都看得到 guide_rev,notice 至少出现不止一次;三份入口第 3 行新句。只跑改动面单元例各一次。设计者下次更新时看 Grok 是否不用提醒就重读(本位记观察)。
